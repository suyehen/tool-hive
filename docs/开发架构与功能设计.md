## 1. 项目概览

ToolHive 是一个独立的工具平台后端项目。它为 CountBot 及其他调用方提供统一的工具目录、检索、授权和执行能力。

### 1.1 核心设计原则

| 原则 | 说明 | 来源 |
|------|------|------|
| 单项目双 API | 一套后端承载管理侧 API 和工具运行侧 API，不拆分独立项目 | Q02 |
| 两类认证隔离 | 管理账号凭据只能访问管理侧 API；调用系统凭据只能访问运行侧 API | Q02、Q07 |
| 管理/运行边界 | 后台角色控制管理操作，工具调用范围控制工具执行，两套体系相互隔离 | Q07 |
| 默认拒绝 | 管理操作和工具调用均采用默认拒绝原则 | Q06 |
| 不物理删除 | 账号、角色、调用系统均逻辑归档不物理删除，保留审计关联 | Q04、Q06、Q08 |
| PostgreSQL 为唯一事实来源 | 工具定义、版本、权限绑定、运行状态以 PG 为准；Chroma 仅为检索派生 | 改造设计 §1 |
| 不可变版本 | 工具更新创建新 `tool_version`，不覆盖既有版本 | 改造设计 §4 |

### 1.2 一期交付范围

```
一期上半部分（管理侧）
├── 管理前端（独立 Web 应用，Nginx 托管）
├── 管理侧 API（/api/admin/**）
├── 管理账号 + 后台角色 + 管理操作项
└── 调用系统 / 能力包 / Provider / 工具 / 版本 / 审核 / 发布

一期下半部分（工具侧）
├── 工具运行侧 API（/api/runtime/**）
├── 调用系统认证（RSA-PSS-SHA256 请求签名）
├── 工具发现（Resolve） + 工具执行（Execute）
├── 工具调用控制（ToolPolicy）
└── 基础 Trace
```

明确不做：监控看板、报表、SSO 实接入、MCP、gRPC、异步长任务、高级发布回滚、成本质量评估、多地域容灾（Q01）。

### 2.2 数据库与基础设施

| 组件 | 用途 | 来源/依据 |
|------|------|-----------|
| PostgreSQL | 核心业务数据（工具目录、账号、角色、调用系统、Trace） | Q03、改造设计 §1 |

### 2.3 安全算法

| 场景 | 算法 | 来源/依据 |
|------|------|-----------|
| 密码哈希 | Argon2id，独立随机盐，支持自动升级 | M02 |
| TOTP | RFC 6238，标准验证器应用 | M02 |
| 请求签名 | RSA-PSS-SHA256，密钥 ≥ 2048 位，MGF1-SHA256，Salt=32 | Q11 |
| 请求体摘要 | SHA-256 | Q11 |
| 签名编码 | Base64URL（无尾部填充） | Q11 |
| 会话 ID | ≥ 256 位安全随机 | M02 |
| Nonce | ≥ 128 位安全随机 | Q11 |
| 临时密码 | 安全随机生成 | M02 |

### 2.4 开发工具

| 组件 | 选型 | 来源/依据 |
|------|------|-----------|
| Lint / Format | ruff（E/F/I/N/W/UP 规则），行宽 100 | `pyproject.toml` |

## 4. 应用架构

### 4.1 FastAPI 子应用挂载

Q02 确认 ToolHive 是单项目双 API，两类 API 共享底层服务。实现上使用 FastAPI 的 `mount()` 将管理侧和运行侧挂载为独立子应用：

```python
# src/toolhive/main.py
from fastapi import FastAPI
from toolhive.api.admin.router import admin_app
from toolhive.api.runtime.router import runtime_app
from toolhive.config import settings

app = FastAPI(
    title=settings.app_name,
    version=settings.app_version,
)

# 管理侧子应用：/api/admin/**
app.mount("/api/admin", admin_app)

# 运行侧子应用：/api/runtime/**
app.mount("/api/runtime", runtime_app)

# 健康检查（不归入任何子应用）
@app.get("/health")
async def health():
    return {"status": "ok"}
```

两个子应用各自拥有独立的路由、中间件和依赖注入体系，但共享 models/、services/ 和 infrastructure/ 层的实现。

### 4.2 中间件链

#### 管理侧（`/api/admin/**`）请求处理链

```
请求 → Nginx HTTPS → Uvicorn
  → SessionMiddleware       # 从共享存储加载会话，附加到 request.state
  → CSRFMiddleware          # 非只读方法校验 CSRF Token + Origin/Referer
  → 路由处理函数
    → Depends(get_current_user)    # 解析会话 → 管理账号
    → Depends(require_operation)   # 校验管理操作项 → 403 或通过
    → 业务逻辑
  → 响应（设置/更新 Cookie）
```

#### 运行侧（`/api/runtime/**`）请求处理链

```
请求 → Nginx HTTPS（内网） → Uvicorn
  → CallerAuthMiddleware    # 校验签名、时间窗口、nonce、IP
    → 提取 system_id → 调用系统状态检查
    → 校验 key_id 归属和状态
    → 重新计算请求体 SHA-256
    → 验证签名
  → 路由处理函数
    → ToolPolicy.Discover / .Execute
    → 业务逻辑
  → 响应
```

### 5.2 关键模型实现要点

#### management_account（Q04 + Q05）

- `id`: UUID，主键
- `username`: 唯一，不可重复分配给其他人员
- `password_hash`: Argon2id 哈希，只存不可逆值
- `external_user_id`: 可空，唯一，SSO 预留字段
- `status`: `enabled` | `disabled` | `locked`
- `login_failures`: 连续失败次数，登录成功后归零
- `locked_until`: 锁定到期时间，到期自动恢复
- `must_change_password`: 布尔标记，临时密码/重置后为 True
- `temp_password_expires_at`: 临时密码过期时间（24 小时）
- 不设 `deleted` 字段——账号不物理删除

#### management_operation（Q06）

- `operation_code`: 主键，稳定唯一，如 `admin_account:view`、`tool:review`
- `display_name`: 可修改
- `status`: `active` | `deprecated`——废弃不可删除和复用
- **由代码定义**：`core/operation_codes.py` 中枚举所有操作码，数据库迁移时同步
- 新增操作码默认只授予超级管理员

#### caller_system（Q08）

- `system_id`: 自动生成，`sys_` 前缀 + UUID，创建后不可变，注销后不复用
- `environment`: `development` | `production`——同项目不同环境分别登记
- `status`: `draft` → `enabled` → `disabled` → `revoked`（`expired` 根据 effective_to 自动判定）
- `effective_from` / `effective_to`: 可为空（长期系统），临时系统必须设置

### 7.1 调用系统认证中间件

**来源**：Q11

运行侧每个请求携带以下 Header：

| Header | 说明 |
|--------|------|
| `X-ToolHive-System-Id` | 调用系统标识 |
| `X-ToolHive-Key-Id` | 公钥记录 ID |
| `X-ToolHive-Timestamp` | UTC Unix 秒 |
| `X-ToolHive-Nonce` | ≥128 位安全随机数 |
| `X-ToolHive-Content-SHA256` | 请求体原始字节 SHA-256 |
| `X-ToolHive-Signature-Version` | 固定 `TOOLHIVE-SIGN-V1` |
| `X-ToolHive-Signature` | Base64URL 编码的 RSA-PSS 签名 |

**待签名字符串**（`\n` 分隔）：

```
TOOLHIVE-SIGN-V1
{system_id}
{key_id}
{timestamp}
{nonce}
{HTTP_METHOD}
{/api/runtime/...}
{normalized_query_string}
{content_type}
{body_sha256_hex}
```

**中间件校验流程**：

```
1. 提取所有 Header → 缺失任一 → 401 "未认证"
2. system_id 存在且状态为 enabled → 否则 401
3. key_id 存在、归属 system_id、状态为 valid → 否则 401
4. timestamp 在服务器时间 ±5 min 内 → 否则 401 "时间窗口外"
5. nonce 首次出现（Redis SETNX, TTL=10min） → 否则 401 "重复请求"
6. 重新计算请求体 SHA-256 → 与 Header 不一致 → 401
7. 拼接待签名字符串，用公钥验证签名 → 失败 → 401
8. 全部通过 → 附加 system_id 到 request.state
```

**关键实现要求**（Q11）：
- 所有失败统一返回 `{"detail": "未认证", "trace_id": "..."}`，不泄露具体原因
- 实现必须提供固定测试向量（含请求内容、待签名字符串、摘要、最终签名）
- 公钥使用 PEM `SubjectPublicKeyInfo` 格式
- nonce 原子写入：`SET key value NX EX 600` → 写入失败即重复

### 7.2 来源 IP 校验（Q10）

```python
async def verify_ip(system_id, request_ip, db) -> bool:
    # 1. 查 caller_ip_rule WHERE system_id AND status = active
    # 2. 无规则 → 拒绝（未配置 IP 规则的系统不能启用）
    # 3. 包含 * 规则 → 直接通过（但 * 与具体规则互斥）
    # 4. 遍历 CIDR 规则 → 任一匹配即通过
    # 5. 无一命中 → 拒绝
```

真实来源 IP 由 Nginx 在转发时覆盖 `X-Forwarded-For`，ToolHive 只信任 Nginx 传递的值（M01 + Q10）。

```
│  └── 模型Key仅后端持有（不暴露给前端和调用系统）                   │
└─────────────────────────────────────────────────────────────┘
```

## 9. 开发规范

### 9.1 代码风格

- **行宽**：100 字符（`pyproject.toml` ruff 配置）
- **Python 版本**：3.12+，使用 `from __future__ import annotations`
- **Lint 规则**：ruff 的 E、F、I（import 排序）、N（命名）、W、UP（pyupgrade）
- **类型标注**：所有公开函数和方法的参数、返回值

### 9.2 异常处理

统一使用 `core/exceptions.py` 中的异常体系：

```python
class ToolHiveError(Exception):
    """基类。"""

class AuthenticationError(ToolHiveError): ...
    # 管理侧登录失败 / 运行侧签名验证失败

class PermissionDeniedError(ToolHiveError): ...
    # 缺少管理操作项 / 工具调用范围不足

class ValidationError(ToolHiveError): ...
    # 业务规则校验失败（如不能禁用最后一个超管）

class NotFoundError(ToolHiveError): ...
    # 资源不存在

class ConflictError(ToolHiveError): ...
    # 状态冲突（如重复启用）

class ServiceUnavailableError(ToolHiveError): ...
    # Redis/DB 不可用
```

FastAPI 全局异常处理器将上述异常映射为对应的 HTTP 状态码。

```
  ├── Nginx 配置模板
  ├── CORS 中间件
  └── 日志脱敏
```

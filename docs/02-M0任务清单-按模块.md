# ToolHive M0 任务清单（按功能模块组织）

> 上游依据：`01-ToolHive平台设计-v0.2.md`
> **组织方式**：按**功能模块**切分，每个模块 = 一块相对独立的代码 + 一组可验收的任务。
> 每个模块都标了「代码位置」与「设计依据」，实现时先打开该模块的代码位置，规则细节查对应设计章节。

---

## 0. 怎么用这份清单

| 说明 | 内容 |
|---|---|
| 模块编号 | `A` ~ `L`，按**依赖顺序**排列 |
| 任务编号 | `<模块><序号>`，如 `C4` |
| 「产出」列 | 该任务要创建/修改的**文件或目录**——实现时打开的就是这些 |
| 「验收」列 | 可**自动或可复现**的判定，不写"完成即可" |
| 估算 | 单位**人日**，含自测，不含联调等待 |

**建议工作方式**：按模块顺序做，每个模块做完就能独立跑通它的测试；跨模块联调放在 `L`。

## 1. 模块依赖图

```
A 工程基座
├── B 持久化与适配层
│   ├── C 领域模型 ────┬── D 授权与策略 ──┐
│   │                  ├── G 接入管线      │
│   │                  └── H 检索 ────────┤
│   └── E 出站执行 ───────────────────────┤
│                                         ↓
│                                    F 执行内核
│                                         │
│         ┌───────────────────────────────┼──────────────┐
│         ↓                               ↓              ↓
│    I REST 前端                     J 管理 CLI      K 评测体系
│         └───────────────┬───────────────┘              │
│                         ↓                              │
│                    L 端到端验收 ←──────────────────────┘
```

**关键路径**：A → B → C → F → I → L
**可并行**：`G`（接入）与 `D`+`E`（策略与出站）互不依赖；`K1`（标注集）是人工活，可与 A/B 同期启动。

# A · 工程基座

**设计依据**：§12 技术选型、§13 目录结构、§14 架构约束与质量基线、§2.1 合规约束

**边界**：本模块不写任何业务逻辑；`core/` 只建空目录与 `__init__.py`。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|

| A3 | 结构化日志与 trace_id | `src/toolhive/observability/logging.py` | 每条日志为 JSON 且带 `trace_id`；**延迟直方图桶**（10/25/50/100/200/500/1000/2000ms）写入日志（§11） |
| A4 | Alembic 初始化 | `alembic.ini`、`alembic/env.py` | 空库上 `alembic upgrade head` 成功 |
| A5 | CI 流水线 | `.github/workflows/ci.yml` | 各段齐全：lint / arch / unit / integration / contract / eval / e2e；任一段失败阻断合并 |

# B · 持久化与适配层

**职责**：把"数据库、缓存、密钥、出站 HTTP"四件基础设施包成后面模块可直接用的接口。
**代码位置**：`src/toolhive/adapters/{db,cache,secrets,upstream}/`
**设计依据**：§7.2 横切关注点、§10.1 凭据与 KEK、§10.2 出站安全、§12 技术选型

**边界**：本模块**不含业务规则**——不判断权限、不算配额、不组装请求。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| B1 | 数据库会话与事务 | `adapters/db/session.py` | `get_db()` 不自动提交；`@transactional` 支持嵌套与 `requires_new`（独立 session 提交，不受外层回滚影响）；单测覆盖三种情况 |
| B2 | 仓储基类 | `adapters/db/repository.py` | 提供按 ID 查询、`with_for_update` 加锁刷新、乐观锁 `row_version` 比对三个能力 |
| B3 | Redis 客户端与 Lua 脚本 | `adapters/cache/client.py`、`adapters/cache/scripts/` | 连接池与超时可控；Lua 脚本以文件管理（令牌桶/滑动窗口/信号量）；**单测用 testcontainers 覆盖原子性** |
| B4 | KEK 与信封加密 | `adapters/secrets/crypto.py` | 读 `TOOLHIVE_KEKS`（JSON 多把）+ `TOOLHIVE_ACTIVE_KEK_ID`；每条凭据独立随机 DEK + AES-256-GCM；按 `kek_id` 解密；**密钥不出现在日志/异常信息里**（单测断言） |
| B5 | 出站 HTTP 客户端 | `adapters/upstream/client.py` | `verify=True`、`follow_redirects=False`、`trust_env=False`；支持整体 deadline 传播；连接池参数可配 |

# D · 授权与策略

**职责**：一切"能不能调、还能调多少"的判断都在这里，且**只在这里实现一次**。
**代码位置**：`src/toolhive/core/policy/`
**设计依据**：§9.1 授权模型与**配额语义**、§9.2 可见集与 pgvector、§9.3 不可区分原则、§7.2 横切关注点与 **fail-open/closed 矩阵**、§7.1 步骤 3/7/8

**边界**：**不认识 HTTP、不认识 MCP、不组装出站请求**。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| D1 | Grant 解析与可见工具集合 | `core/policy/authorization.py` | 返回该 Principal 可见的 `tool_id` 集合；**Redis 缓存 key = `visible:{principal_id}:{visible_ver}`（不含 scope）**；Grant/Tool/Provider 变更时 `INCR visible_ver`；TTL 60s 兜底；测试覆盖"授权收回后最迟 60s 生效" |
| D2 | 授权判定 | `core/policy/authorization.py` | **不可区分原则**：不存在 / 无权 / 已停用 / 无已发布版本 / 版本或通道不可用——**五者返回完全相同的拒绝结果**（§9.3） |
| D3 | 配额（QPS / 日配额） | `core/policy/quota.py` | **每个命中的 grant 各自独立计数，任一超限即拒绝**（§9.1）；Redis key 含 `scope_type:scope_value`；**QPS 与日配额是两个独立入口**（分处流水线第 3 / 第 7 步）；测试覆盖"增加 grant 不增加额度" |
| D4 | 并发信号量 | `core/policy/concurrency.py` | 基于 Redis；**支持归还**（§7.1 归还矩阵）；测试覆盖并发 100 请求只放行限额条数 |
| D5 | 幂等（两段式） | `core/policy/idempotency.py` | ① 查询与认领分离；② 键绑定请求指纹，不符返回 `TH_IDEMPOTENCY_KEY_REUSED`；③ 结果缓存受 `idempotency_ttl`(24h) 与 `idempotency_cache_max_bytes`(256KB) 约束，**超限只缓存状态并返回 `result: null` + `idempotency_replayed: true`**；④ 测试覆盖"带确认令牌的重试能命中缓存" |
| D6 | 确认令牌 | `core/policy/confirmation.py` | 条件 UPDATE + `rowcount` 原子消费；过期标记**独立事务提交**（不随外层回滚丢失）；重放/错配返回 `TH_CONFIRMATION_INVALID` |
| D7 | 熔断 | `core/policy/circuit_breaker.py` | 按 Provider 维度；阈值/窗口/打开时长可配；**位置在第 7 步，不在第 3 步** |
| D8 | 依赖故障降级矩阵 | `core/policy/degradation.py` | 实现 §7.2 矩阵：幂等/确认 **fail-closed** → `TH_DEPENDENCY_UNAVAILABLE`；QPS/日配额/并发 **fail-open + 告警**；可见集缓存**绕过直查**；PG 不可用一律 fail-closed。**测试逐格覆盖** |

# E · 出站执行

**职责**：把"工具 + 参数"变成一次受控的对外调用。
**代码位置**：`src/toolhive/core/providers/`
**设计依据**：§5.2 字段映射、§10.2 出站安全、§13.1 工具实现放哪、§7.1 第 9/10 步

**边界**：**不做授权、不算配额**；`mcp` 类型 Provider 属 M1，M0 只做 `http` 与 `local`。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| E1 | 出站请求构建 | `core/providers/http.py` | `path_template` 支持 **`{arg}` 占位符替换**；参数可落 query / body / headers 三种位置；支持 `$.path` 取值与常量；超时来自 Binding |
| E2 | SSRF 四道防线 | `core/providers/ssrf.py` | ① 域名白名单（含 `*.` 通配）② 全量 DNS 解析后逐地址校验（拒回环/链路本地/云元数据/多播/保留；私网需显式 CIDR）③ **固定已校验 IP 发起连接** ④ 禁重定向 + `trust_env=False`。**复用上一版用例思路**：`git show d672d4d:tool-hive/tests/runtime/test_outbound.py` |
| E3 | 凭据注入 | `core/providers/credential_injector.py` | 出站前解密并注入 header/query；**解密失败 fail-closed 且触发告警**（§10.1）；凭据值不出现在日志、异常、Trace 中 |
| E4 | local provider | `core/providers/local.py` | 按 `builtin_tools/` 注册表执行纯函数；准入规则由 CI 断言（A6） |
| E5 | 统一出站接口与结果 | `core/providers/base.py` | 抽象 `Provider.execute(binding, provider, arguments) -> dict`；返回统一错误码（超时 → `TH_UPSTREAM_TIMEOUT`，上游 4xx → `TH_UPSTREAM_REJECTED`，5xx/连接失败 → `TH_UPSTREAM_ERROR`） |

# F · 执行内核

**职责**：**全平台唯一一份执行编排**。两个前端都只调它。
**代码位置**：`src/toolhive/core/invocation/`
**设计依据**：**§7.1 阶段时序（13 步，顺序是权威）**、§7.2 横切关注点 + 幂等缓存规则 + 降级矩阵、§7.3 内核入口、**§7.4 错误模型（20 个码）**

**边界**：不 import 任何 Web 框架；**不认识 HTTP 状态码与 MCP**——只产出 `TH_*` 错误码。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| F1 | 内核契约 | `core/invocation/contracts.py` | `InvocationRequest` / `InvocationResult`（§7.3）；`protocol` 仅用于审计、不影响行为 |
| F2 | 13 阶段流水线 | `core/invocation/pipeline.py` | **严格按 §7.1 顺序**：解析 → 授权 → QPS/时间窗/IP → **幂等查询** → 参数校验 → 确认令牌 → **日配额/并发/熔断** → 幂等认领 → 凭据注入 → 出站 → 输出校验 → 记录 → 返回。**测试用打桩记录调用序列，逐阶段断言顺序** |
| F3 | 错误模型 | `core/invocation/errors.py` | 20 个 `TH_*` 码齐全，每个带 HTTP 状态与 `retryable`（§7.4 表为权威）；**内部原因不外泄**（SSRF 拦截映射为 `TH_UPSTREAM_ERROR`） |
| F4 | 资源归还 | `core/invocation/pipeline.py` | 实现 §7.1 归还矩阵五格：认领失败 / 凭据解密失败 / **出站前校验失败** → 归还日配额与并发；**实际出站失败 / 输出校验失败** → 日配额不退、并发 `finally` 释放。**逐格测试** |
| F5 | Invocation 与审计落库 | `core/invocation/recorder.py` | 只存摘要与 SHA-256（**不存明文参数与结果**，§11.1）；写 `Invocation` + `AuditLog`；凭据使用单独记一条（§11） |

# H · 检索

**职责**：把一句话变成候选工具列表，并对召回率负责。
**代码位置**：`src/toolhive/retrieval/`
**设计依据**：**§6.1 接口契约**、§6.2 流水线与 pg_trgm、§6.3 上下文预算、§6.4 embedding 服务、§6.5 索引版本化、§6.6 降级、§6.7 指标与延迟预算

**边界**：**请求路径上不许出现生成式模型**；M0 不做精排（接口留位）、不做中文分词。

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| H1 | embedding 客户端 | `retrieval/embedding/client.py` | 在线单条（**p95 预算 60ms、超时上限 800ms**）+ 离线批量（分批、限流、**断点续跑**，依赖 `content_hash` 跳过未变更）；失败抛 `EmbeddingUnavailable` 供上层降级；首次调用**探测维度**写入 `IndexMeta` |
| H2 | 索引构建 | `retrieval/index/builder.py` | 关键词用 **`pg_trgm`**（不引入分词方案）；向量表带 `index_version`，支持**双版本共存**；重建命令支持 `--model` / `--index-version`（**不依赖 `embedding.model`，避免死锁**，§6.5） |
| H3 | 混合检索 | `retrieval/search.py` | 严格按 §6.2：**先按可见集合预过滤（`WHERE tool_id = ANY(...)`）→ scope 收窄 → 关键词 ∥ 向量 → RRF → top-k**；**必须先过滤再排序**；`k` 上限 50、**不支持翻页**（§6.1）。测试：窄权限 Principal 仍能拿满 k 条 |
| H4 | taxonomy 数据层 | `retrieval/taxonomy.py` | 返回经权限过滤的业务域/系统树 + `tool_count` |
| H5 | 精排接口（no-op） | `retrieval/rerank/` | 统一 `Reranker` 接口 + **no-op 实现（默认）**；配置项 `retrieval.rerank.{enabled,endpoint,model,api_key,timeout_ms,max_candidates}`；**代码保留 TODO："reranker 供应商待定，当前走降级路径"**（§6.2） |
| H6 | 检索事件记录 | `retrieval/events.py` | 记 `SearchEvent`（query 截断 512 + **默认脱敏四条正则**、top_k、degraded、latency）；**`search` 不写 `Invocation`**（§11.1） |
| H7 | 降级逻辑 | `retrieval/search.py` | 向量不可用 → 关键词 + `degraded=true`；精排不可用 → RRF + `degraded=true`；**两者都不可用 → `TH_RETRIEVAL_UNAVAILABLE`**，不返回未排序的全量列表（§6.6） |

## 3. 实现顺序建议

| 批次 | 模块 | 说明 |
|---|---|---|
| 第 1 批 | **A** | 基座，必须最先 |
| 第 2 批 | **B**、**K1**（标注集） | B 解锁所有模块；K1 是人工活，与 B 并行 |
| 第 3 批 | **C** | 领域模型，后面全部依赖它 |
| 第 4 批 | **D**、**E**、**G** | 三者互不依赖，可并行分给不同人 |
| 第 5 批 | **F** | 执行内核，需要 D + E 就位 |
| 第 6 批 | **H**、**J** | H 依赖 C；J 依赖 C + D + G |
| 第 7 批 | **I** | 依赖 F + H |
| 第 8 批 | **K2/K3**、**L** | 收口 |

**两人分工建议**：
- 甲：A → B → C → F → I（关键路径）
- 乙：K1 → G → H → J → K2/K3
- 汇合做 L

## 4. 每个模块的"别做这些"

为防实现时越界——尤其 `core/` 与 `frontends/` 的边界：

| 模块 | 不许做 |
|---|---|
| **B** | 不判断权限、不算配额、不组装请求 |
| **C** | 不做授权判定、不做检索、不发请求 |
| **D** | 不认识 HTTP / MCP；不组装出站请求 |
| **E** | 不做授权、不算配额 |
| **F** | **不 import 任何 Web 框架**；不认识 HTTP 状态码与 MCP |
| **G** | M0 不做 MCP 导入；不接 LLM |
| **H** | 请求路径不许出现生成式模型；M0 不做精排、不做分词 |
| **I** | 不含任何业务规则；只 import 内核 |
| **J** | 不持有 KEK、不参与凭据解密 |

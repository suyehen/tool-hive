# ToolHive M0 任务清单（按功能模块组织）

> 上游依据：`01-ToolHive平台设计-v0.2.md`
> **组织方式**：按**功能模块**切分，每个模块 = 一块相对独立的代码 + 一组可验收的任务。
> 每个模块都标了「代码位置」与「设计依据」，实现时先打开该模块的代码位置，规则细节查对应设计章节。

---

## 0. 怎么用这份清单

| 说明 | 内容 |
|---|---|
| 模块编号 | `A` ~ `L`，按**依赖顺序**排列 |
| 任务编号 | `<模块><序号>`，如 `C4` |
| 「产出」列 | 该任务要创建/修改的**文件或目录**——实现时打开的就是这些 |
| 「验收」列 | 可**自动或可复现**的判定，不写"完成即可" |
| 估算 | 单位**人日**，含自测，不含联调等待 |
| **引用原则** | 任务里**只写"要做什么"与契约标识**（文件路径、配置项名、函数名、错误码名、实体名）；**具体数值与规则条文一律引用设计章节**（如"按 §7.2 矩阵"），**不复制**。原因：本清单是派生物，复制来的文案会产生第二个漂移面 |

**建议工作方式**：按模块顺序做，每个模块做完就能独立跑通它的测试；跨模块联调放在 `L`。

## 1. 模块依赖图

```
A 工程基座
├── B 持久化与适配层
│   ├── C 领域模型 ────┬── D 授权与策略 ──┐
│   │                  ├── G 接入管线      │
│   │                  └── H 检索 ────────┤
│   └── E 出站执行 ───────────────────────┤
│                                         ↓
│                                    F 执行内核
│                                         │
│         ┌───────────────────────────────┼──────────────┐
│         ↓                               ↓              ↓
│    I REST 前端                     J 管理 CLI      K 评测体系
│         └───────────────┬───────────────┘              │
│                         ↓                              │
│                    L 端到端验收 ←──────────────────────┘
```

**关键路径**：A → B → C → F → I → L
**可并行**：`G`（接入）与 `D`+`E`（策略与出站）互不依赖；`K1`（标注集）是人工活，可与 A/B 同期启动。

| # | 任务 | 产出 | 验收 |

# B · 持久化与适配层

**边界**：本模块**不含业务规则**——不判断权限、不算配额、不组装请求。

| # | 任务 | 产出 | 验收 |

| B2 | 仓储基类 | `adapters/db/repository.py` | 提供按 ID 查询、`with_for_update` 加锁刷新、乐观锁 `row_version` 比对三个能力 |

## 3. 实现顺序建议

| 批次 | 模块 | 说明 |
|---|---|---|
| 第 1 批 | **A** | 基座，必须最先 |
| 第 2 批 | **B**、**K1**（标注集） | B 解锁所有模块；K1 是人工活，与 B 并行 |
| 第 3 批 | **C** | 领域模型，后面全部依赖它 |
| 第 4 批 | **D**、**E**、**G** | 三者互不依赖，可并行分给不同人 |
| 第 5 批 | **F** | 执行内核，需要 D + E 就位 |
| 第 6 批 | **H**、**J** | H 依赖 C；J 依赖 C + D + G |
| 第 7 批 | **I** | 依赖 F + H |
| 第 8 批 | **K2/K3**、**L** | 收口 |

**两人分工建议**：
- 甲：A → B → C → F → I（关键路径）
- 乙：K1 → G → H → J → K2/K3
- 汇合做 L

## 4. 每个模块的"别做这些"

为防实现时越界——尤其 `core/` 与 `frontends/` 的边界：

| 模块 | 不许做 |
|---|---|
| **B** | 不判断权限、不算配额、不组装请求 |
| **C** | 不做授权判定、不做检索、不发请求 |
| **D** | 不认识 HTTP / MCP；不组装出站请求 |
| **E** | 不做授权、不算配额 |
| **F** | **不 import 任何 Web 框架**；不认识 HTTP 状态码与 MCP |
| **G** | M0 不做 MCP 导入；不接 LLM |
| **H** | 请求路径不许出现生成式模型；M0 不做精排、不做分词 |
| **I** | 不含任何业务规则；只 import 内核 |
| **J** | 不持有 KEK、不参与凭据解密 |

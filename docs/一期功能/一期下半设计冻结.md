## 1. Catalog 领域模型

### 1.1 实体与关系

| 实体 | 职责 | 与其它实体的关系 |
|------|------|------------------|
| Provider | 执行通道：`builtin`（平台内置实现）或 `http`（外部 HTTP 目标） | 工具版本通过执行绑定关联到 Provider（多对一） |
| 能力包（CapabilityPack） | 工具的打包与调用系统授权单元 | 与工具多对多；与调用系统多对多（调用系统工具范围） |
| 工具（Tool） | 目录条目，含基础信息与可发现性/可执行性 | 持有多个工具版本；可被多个能力包引用 |
| 工具版本（ToolVersion） | 可执行内容单元：Schema、执行绑定、风险等级 | 属于工具（多对一）；引用一个执行绑定 |
| 执行绑定（ExecutionBinding） | 工具版本 ↔ Provider 的固定映射 | 属于工具版本（一对一）；引用 Provider |

### 1.2 命名空间与编码规则

- 命名空间采用点分格式 `{项目}.{子域}`，例如 `math.basic`；一级为项目，二级为子域，暂不支持更深层级。
- 工具编码在命名空间内唯一；完整工具标识为 `{namespace}.{tool_code}`，如 `math.basic.calculator`。
- Provider、能力包编码全局唯一，不归属命名空间（系统级配置对象）。
- 工具版本号由管理员维护（如 `1.0.0`），同一工具下版本号唯一。
- 命名空间、工具编码、Provider 编码、能力包编码一经创建不可修改；需要变更时新建对象并归档旧对象。

### 1.3 环境边界

- Catalog 对象本身不区分环境；环境隔离通过调用系统实现——调用系统按"外部项目 + 运行环境"分别登记（不同 `system_id`、认证凭据、来源 IP 规则与工具范围）。
- 同一工具发布后，由各调用系统的工具范围配置决定其开发/生产环境的可见性。

### 1.4 唯一性约束与状态字段

- 唯一性：工具 = 命名空间 + 工具编码；工具版本 = 工具 + 版本号；Provider / 能力包 = 全局编码。
- 状态字段统一使用代码层枚举（`core/enums.py`），数据库不加 CHECK（沿用工程约定）。
- 业务表审计字段 `create_by` / `update_by`；关键管理操作接入 `AuditService`。

## 2. 状态机

### 2.1 对象范围（谁走审核发布）

| 对象 | 状态集合 | 是否参与审核发布 |
|------|----------|------------------|
| 工具版本 | DRAFT / PENDING_REVIEW / APPROVED / REJECTED / PUBLISHED / DISABLED / WITHDRAWN / ARCHIVED | 是，唯一走完整流程的对象 |
| 工具 | ENABLED / DISABLED / ARCHIVED | 否，管理操作直接生效 + 审计 |
| Provider | ENABLED / DISABLED / ARCHIVED | 否，同上 |
| 能力包 | ENABLED / DISABLED / ARCHIVED | 否，同上 |
| 执行绑定 | 有效 / 失效（随版本状态生效，版本归档即失效） | 否 |

理由：真正被运行链路执行的是工具版本（Schema、参数、执行绑定），审核发布只针对会改变线上行为的内容；工具 / Provider / 能力包是配置骨架，改动直接生效并以管理审计留痕。

### 2.2 工具版本状态流转

- DRAFT →（送审）→ PENDING_REVIEW
- PENDING_REVIEW →（通过）→ APPROVED
- PENDING_REVIEW →（驳回）→ REJECTED →（修改）→ DRAFT
- APPROVED →（发布）→ PUBLISHED
- PUBLISHED →（停用）→ DISABLED；DISABLED →（重新启用）→ PUBLISHED
- PUBLISHED / DISABLED →（撤回）→ WITHDRAWN（保留历史，不可直接恢复运行）
- DRAFT / PENDING_REVIEW / APPROVED / PUBLISHED / DISABLED / WITHDRAWN →（归档）→ ARCHIVED（终态，不可恢复）

### 2.3 默认版本与发布切换

- 每个工具同时最多一个默认版本；默认版本必须是 PUBLISHED。
- 发布版本时必须显式声明 `set_default`（true/false）；置为默认时原默认版本自动降级为非默认。
- 仅默认版本参与 Discover / Execute 的默认解析；非默认已发布版本可通过显式版本号 Resolve / Execute。

### 2.4 在途调用处理

- 已受理、正在执行的请求（在途）不打断，执行完成后正常返回结果，Trace 记录实际使用的版本。
- 新到达的请求按最新状态判断：已停用 / 已撤回 / 已归档则拒绝；新版本发布后新请求按默认版本执行。
- 版本切换不打断在途请求；一期不提供取消在途、回滚或回调（属于明确不做的异步任务治理范围）。

## 3. 运行 API 契约

### 3.1 接口清单

| API | 路径 | 职责 |
|-----|------|------|
| Resolve | `POST /api/runtime/v1/tools/resolve` | 按工具 ID / 完整标识 / 版本精确解析，不依赖 Chroma |
| Discover | `POST /api/runtime/v1/tools/discover` | 自然语言检索候选工具，返回受控候选、排序与覆盖度 |
| Execute | `POST /api/runtime/v1/tools/{tool_code}/execute` | 二次授权、参数校验、执行与结果标准化 |
| Confirmations | `POST /api/runtime/v1/confirmations` | 高风险操作确认申请、令牌校验、过期处理与防重放 |

- `tool_code` 为完整工具标识 `{namespace}.{tool_code}`。
- Execute 不得依赖 Discover 旧结果，必须重新校验调用系统、ToolContext、工具状态、范围、策略、真实参数与确认状态。

### 3.2 错误模型

- 采用 HTTP 状态码 + 稳定业务错误码；业务错误码统一前缀 `RUNTIME_`，示例：
  - `RUNTIME_AUTH_INVALID_SIGNATURE`、`RUNTIME_AUTH_EXPIRED_TIMESTAMP`、`RUNTIME_AUTH_REPLAYED_NONCE`、`RUNTIME_AUTH_IP_NOT_ALLOWED`、`RUNTIME_AUTH_INVALID_SYSTEM`
  - `RUNTIME_SCOPE_NOT_ALLOWED`、`RUNTIME_TOOL_NOT_FOUND`、`RUNTIME_TOOL_NOT_AVAILABLE`、`RUNTIME_CONFIRMATION_REQUIRED`、`RUNTIME_CONFIRMATION_INVALID`
  - `RUNTIME_PARAMETER_INVALID`、`RUNTIME_IDEMPOTENCY_CONFLICT`、`RUNTIME_RATE_LIMITED`
  - `RUNTIME_PROVIDER_ERROR`、`RUNTIME_PROVIDER_TIMEOUT`、`RUNTIME_PROVIDER_SSRF_BLOCKED`、`RUNTIME_RETRIEVAL_UNAVAILABLE`、`RUNTIME_INTERNAL_ERROR`
- 统一错误体：`{"code": "RUNTIME_*", "message": "...", "trace_id": "..."}`；不返回堆栈、敏感字段或未授权信息。

### 3.3 幂等

- Execute 请求可携带幂等键（Header `Idempotency-Key`，调用系统维度唯一）；写操作与可能产生外部副作用的执行必须携带。
- 服务端按"调用系统 + 幂等键"在配置窗口内（默认 24 小时，可配置）去重，重复请求返回首次结果或冲突语义（`RUNTIME_IDEMPOTENCY_CONFLICT`）。
- 确认令牌一次性消费，不可重放。

### 3.4 版本兼容

- v1 内只做向后兼容演进：允许响应新增字段、请求新增可选字段；删除 / 重命名 / 改变含义的字段必须升级版本路径。
- 调用方必须忽略响应中未知字段；请求中未知字段一期按拒绝处理（防绕过），后续如需兼容另行确认。

## 4. 请求签名

### 4.1 协议与算法

- 认证协议固定 `TOOLHIVE-SIGN-V1`，一期、二期不引入其他认证协议（HMAC、mTLS、API Key、OAuth 等全部排除）。
- 算法注册表：`RSA-PSS-SHA256`（必选）+ `Ed25519`（算法标识 `"Ed25519"`）；SM2-SM3 不纳入一期。
- RSA-PSS：PSS + MGF1(SHA256)，salt length 固定 32；RSA 公钥位长下限取 `signing_key_min_bits`（默认 2048）。
- 验签复用 `runtime/authentication/verifiers/` 工厂；每把公钥绑定单一算法，按 `key_id` 查公钥记录分发，未知算法默认拒绝。

### 4.2 请求头

| Header | 说明 |
|--------|------|
| `X-ToolHive-System-Id` | 调用系统 `system_id` |
| `X-ToolHive-Key-Id` | 验签公钥 `key_id` |
| `X-ToolHive-Timestamp` | Unix 秒级时间戳 |
| `X-ToolHive-Nonce` | 调用系统生成的唯一随机串（每次请求不同） |
| `X-ToolHive-Signature` | base64 签名 |
| `X-ToolHive-Trace-Id` | 可选透传，未传由平台生成 |
| `Idempotency-Key` | 可选幂等键（execute 写操作建议必填） |

### 4.3 Canonical 串

`METHOD\nPATH\nQUERY\nTIMESTAMP\nNONCE\nSHA256_HEX(body)`

- PATH 为完整版本路径（如 `/api/runtime/v1/tools/resolve`）。
- QUERY 为规范化排序后的 `key=value`（`&` 连接，无查询串时为空行）。
- body 为空时 `SHA256_HEX` 取空字符串的 SHA-256。
- 签名内容覆盖 HTTP 方法、完整路径、时间戳、Nonce 与请求体摘要；未覆盖字段不得参与签名。

### 4.4 时间窗口与防重放

- 时间窗口默认 300 秒（`signature_time_window_seconds`），超窗拒绝。
- Nonce 防重放存 Redis：key `toolhive:nonce:{system_id}:{nonce}`，TTL 取 `nonce_retention_minutes`（默认 10 分钟）；已存在即 `RUNTIME_AUTH_REPLAYED_NONCE`。
- Redis 等安全依赖不可用时默认拒绝，不允许降级放行。

### 4.5 密钥选择与轮换

- 调用系统公钥支持多把并行有效（轮换窗口）；`key_id` 精确选择验签公钥。
- 公钥停用 / 撤销即时生效；撤销后使用该 `key_id` 的请求被拒绝。
- 调用系统生命周期、有效期、紧急禁用、来源 IP 规则在每次请求实时校验；停用 / 注销 / 密钥撤销立即影响后续请求。

## 5. ToolContext

### 5.1 字段与传入方式

- 请求体顶层 `context` 对象，字段：`user_id`、`tenant_id`、`role`、`channel`、`session_id`；均为可选字符串（UTF-8，长度上限按字段配置）。
- `trace_id` 通过 `X-ToolHive-Trace-Id` Header 透传，未传由平台生成；响应头与错误体携带 `trace_id`。
- 来源 IP、入口标识由入口中间件注入，调用系统不可伪造。

### 5.2 可信边界（声明制）

- 调用系统已通过签名、来源 IP 与调用范围校验，一期平台信任其声明的业务身份字段（Trace 中来源标注 `caller-declared`），不做外部身份源验证（一期无 SSO，属明确不做范围）。
- 平台仅校验：字段格式（类型、长度、字符集）、必填（按调用系统配置的 identity 约束，一期默认全部可选）与调用系统允许的业务身份范围。
- 未知业务身份字段默认拒绝（防绕过）；格式非法返回 `RUNTIME_PARAMETER_INVALID`。
- ToolContext 只能参与工具调用控制计算（如按租户过滤），不得用于绕过调用系统级授权；默认拒绝继续生效。

## 6. 工具调用控制

- 计算链（按序校验，全部通过才允许）：
  1. 调用系统状态、有效期、紧急禁用、来源 IP；
  2. 运行 API 范围（`allowed_api_patterns` 实时生效）；
  3. 调用系统工具范围（能力包 / 工具 / 命名空间编码，阶段 1 完成 Catalog 真实引用校验回补）；
  4. 工具及工具版本发布状态；
  5. ToolContext 业务身份范围；
  6. 风险等级与确认状态（高风险 / 写操作需确认令牌）。
- 默认拒绝：任一环节未配置、未授权、失效、上下文不可信或安全依赖不可用时拒绝。
- 可发现与可执行区分：Discover / Resolve 返回通过范围与发布状态校验的工具；Execute 时重新计算二次授权（含确认状态与真实参数）。
- 信息保护：未授权工具的完整 Schema、目标地址与敏感策略信息不得出现在 Discover / Resolve / 错误响应中。

## 7. 首批工具契约

- 首批工具为数学计算类占位工具（四则运算、幂、取模等，如 `math.basic.calculator`），目的为打通 Catalog → 认证 → 发现 → 执行 → Provider → Trace 全链路。
- Provider 类型一期支持两种：
  - `builtin`：平台内置实现，无外部出站、无凭据；首批数学工具使用该类型。
  - `http`：外部 HTTP 目标，受第 8 节 Provider 出站规则约束；后续真实外部工具按此类型接入。
- 首批工具边界：只读计算、幂等、无业务数据、无凭据；风险等级 low；超时短（默认 5 秒）；重试最多 1 次；响应为标准 JSON 结果。
- 错误转换：Provider 层错误统一转换为 `RUNTIME_PROVIDER_*` / `RUNTIME_PARAMETER_INVALID`，不向外暴露内部地址与堆栈。
- 与既有文档"首批 HTTP 工具接入（真实外部 API 契约）"表述的差异：本决策按阶段 0 确认执行，已在《一期下半开发计划》《一期下半待实现功能》《一期目标》补充记录对齐；真实外部 HTTP 工具在后续批次按同一契约接入，不改变一期受控出站要求。

## 8. Provider 出站规则

- 统一 `ProviderGateway`：管理、运行等所有业务出站必须经过，不得绕过；调用方与 LLM 不得决定 URL、方法、认证 Header 或未声明参数。
- 仅按已审核的固定映射生成请求；`http` 类型的域名、端口、路径模板、协议、参数映射与允许 Header 在审核时固定。
- SSRF 防护：DNS 解析后校验全部 IPv4 / IPv6 地址，默认拒绝回环、链路本地、云元数据（169.254.169.254）、多播与未授权私网地址。
- 网络策略：公网 HTTPS 默认允许；内网目标必须显式配置允许 CIDR 后才放行。
- TLS：强制 HTTPS 与证书校验；默认不自动跟随重定向，如需跟随必须每跳重新校验目标与 TLS。
- 资源限制：请求体 / 响应体大小、Header 数量、连接时间、读取时间、总执行时间与并发数（读写区分）。
- 幂等 / 重试 / 熔断：读操作可有限重试；写操作外部状态不明时不得盲目自动重试；熔断按 Provider 目标维度。
- 响应处理：格式校验、大小限制、脱敏、标准化、错误转换，并记录 Trace；Provider 返回内容不得直接作为平台指令或新工具定义。
- 健康检查：Provider 启用时进行基础目标校验（域名解析、HTTPS 可达性），失败给出明确错误。

## 9. 检索与可用性

- PostgreSQL 是工具定义、版本、发布状态与授权的唯一事实来源。
- 嵌入式 Chroma 保存可全量重建的 Catalog 派生索引（`persist_directory=/vdb/tool-hive/chroma`，复用 `VectorIndex` 接口）；一期单实例、写并发固定为 1。
- Embedding：采用腾讯云 TokenHub embedding API——端点 `POST https://tokenhub.tencentmaas.com/v1/embeddings`，模型 `kinfra-text-embedding-4b`，认证为 Bearer Token；API Key 通过 `model_api_key` 配置注入，不写入代码与文档。
- 向量落库：一期继续使用 Chroma；pgvector 的优势留待二期多实例 / 服务化时评估，`VectorIndex` 接口已预留切换抽象。
- Discover：优先 Chroma 向量检索；Chroma 或 Embedding 不可用时降级为 PostgreSQL 有界关键词检索（工具编码、名称、关键词、标签），候选数量上限默认 20。
- 降级候选仍须完成发布状态、调用系统范围与工具调用控制校验，不得扩大可见范围；无法形成可靠候选时返回 `RUNTIME_RETRIEVAL_UNAVAILABLE` 或空结果，不返回未授权信息。
- 覆盖度：Discover 响应返回候选数量与覆盖度信息（基础版）。
- 精确 Resolve 与按工具 ID / 完整标识查询不依赖 Chroma。
- 索引同步：Catalog 变更通过 Outbox 投递到 Redis / Chroma 派生索引，支持失败查询与重试；提供 `rebuild-chroma` 全量重建命令。

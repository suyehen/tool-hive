### 3.2 一期下半部分 Provider 出站与执行安全待开发项

> **归属说明**：本节属于一期下半部分工具应用模块的待开发和待确认内容，不属于一期上半部分管理模块的完成判定。上半部分对外查询能力的具体范围另行确认。

#### 已确认边界

- 一期调用系统认证只保存调用系统公钥；调用系统私钥由调用系统自行保管。
- 一期不保存目标业务系统的密码、API Key、OAuth Secret 或客户端私钥。
- 一期不引入 Secret Store、`credential_ref` 或目标系统凭据代持接口。
- 如果首批工具需要目标系统凭据，该工具不得进入一期交付，转入二期重新确认。
- ToolHive 只能通过已审核的固定 Provider 映射访问外部接口，不能把调用方或 LLM 传入的 URL、方法、认证 Header 当作执行目标。
- Provider 执行必须经过统一的 `ProviderGateway`，管理 Controller、运行 Controller 和其他业务模块不得自行访问任意外部地址。
- 一期不执行任意 Python、Shell、文件系统操作或动态代码；高风险宿主能力转入后续独立执行器评估。

#### 待确认和待实现的出站安全规则

- 固定 Provider 目标的域名、端口、路径模板、HTTP 方法、参数映射和允许 Header。
- DNS 解析后对全部 IPv4/IPv6 地址进行校验，拒绝回环、链路本地、云元数据、多播和未授权私网地址；确需访问内部系统时，必须显式配置允许的 CIDR。
- 一期默认禁止自动跟随 HTTP 重定向；如后续允许，每一跳都必须重新校验目标和 TLS。
- 强制 HTTPS 和证书校验，不允许关闭 TLS 验证或使用调用方指定的代理。
- 应用层目标校验与生产主机防火墙形成双层出站限制；动态地址 Provider 是否通过独立 Egress Proxy，需要根据实际 Provider 再确认。
- 限制请求体、响应体、Header 数量、连接时间、读取时间、总执行时间和并发数。
- 读操作与写操作采用不同的超时、幂等、重试和熔断规则；写操作在外部状态未知时不得盲目自动重试。
- Provider 返回结果必须经过格式校验、大小限制、标准化、脱敏和 Trace 记录，不能把返回内容直接当作平台指令或新的工具定义。
- Provider 出站失败、目标校验失败、TLS 失败、响应超限和熔断状态需要形成可查询的运行日志和审计信息。

#### 与一期上半部分的关系

- 上半部分只为下半部分提供调用系统、公钥、工具目录、审核发布和安全规则等配置前提。
- 下半部分负责将这些已发布配置接入运行 API，并完成 Discover、Execute 和 Provider 受控调用。
- 上半部分对外查询能力的具体对象、接口和范围尚未冻结，不在本节中预设。

### 3.3 Trace 与审计阶段安排

Trace 与审计整体放在一期下半统一设计，不作为一期上半管理模块的完成判定。这样可以围绕真实的工具发现、工具执行和 Provider 调用链路确定追踪边界，再回头补齐管理侧操作的关联记录。

一期下半至少需要确认和实现：

- 运行请求的 `trace_id` 生成、传递和错误关联；
- 调用系统认证、授权、Discover、Execute、Provider 调用和结果处理的关键记录；
- 管理变更和运行决策的基础审计、脱敏和留存规则；
- Trace 与审计记录的查询关联方式。

一期上半现有的登录、权限和管理配置功能不因暂未实现 Trace/审计而改变；相关能力在一期下半开始前统一回补和验收。生产级健康检查、metrics、监控告警、备份恢复、RPO/RTO、发布迁移和多实例高可用不属于本节，延后至二期。

| 前置项 | 与下半部分的关系 |
|--------|------------------|

| ToolContext 契约 | 工具调用控制必须基于可信的用户、租户、角色和渠道上下文进行判断。 |

| 首批外部 HTTP API 契约 | Provider 执行需要固定的请求/响应、业务权限、幂等、超时和重试约定。 |
| Trace 与审计要求 | 归入一期下半统一设计；工具运行链路先确定基础 `trace_id` 和审计字段，再回补管理侧关联和留存规则。 |

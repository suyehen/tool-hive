## 模块一：管理账号生命周期

> 来源：Q04

### 1.1 首个超级管理员初始化

- 首次部署时通过**一次性初始化命令**创建首个超级管理员。
- 用户名和初始密码由部署人员提供，**不在代码中内置固定账号或密码**。
- 初始化仅在尚无管理账号时执行；已有账号时不得重复创建或覆盖。

### 1.2 账号创建与维护

- **不开放注册入口和公开注册 API**；后续账号只能由具备账号管理能力的管理员通过管理后台创建。
- 新建账号使用**临时密码**，首次登录必须修改。
- 登录用户可以修改自己的密码。
- 管理员可以**重置他人密码**，但不能查看原密码；重置后使用临时密码，被重置者下次登录必须修改。
- 密码只保存**不可逆哈希**，不保存或回显明文。

### 1.3 账号状态控制

- 管理账号支持**启用、禁用、锁定**三种状态。
- **不进行物理删除**；禁用或离职账号保留基本信息和历史审计关联。
- 用户名**不得重新分配**给其他人员。

### 1.4 登录失败锁定

- 默认**连续登录失败 5 次后锁定 30 分钟**。
- 失败次数和锁定时间均可配置。
- 锁定到期后自动恢复；具备账号管理能力的管理员可提前解锁。
- 登录成功后**清空失败次数**。

### 1.5 强制下线与会话撤销

- 管理员可对指定账号执行**强制下线**。
- 以下情况**立即撤销该账号的全部有效会话**：
  - 账号被禁用
  - 密码被重置
  - 进行离职处理

### 1.6 超级管理员保护规则

- 系统必须始终保留**至少一个启用状态的超级管理员**。
- 不允许禁用最后一个超级管理员。
- 不允许当前管理员停用**自己的账号**。

## 模块二：登录认证与会话安全

> 来源：Q05、M02

### 2.1 本地登录

- 一期**仅支持本地用户名和密码登录**，不开放注册。
- 登录成功后建立可撤销的管理会话。

### 2.2 密码安全规则

| 规则项 | 要求 |
|--------|------|
| 长度 | 最少 12 位，最多 128 位 |
| 复杂度 | 不强制大小写字母、数字和特殊字符同时出现 |
| 禁止项 | 不得与用户名、工号或常见弱密码相同 |
| 历史限制 | 不能与最近 5 个历史密码重复 |
| 哈希算法 | Argon2id，独立随机盐，支持自动升级和重新哈希 |
| 定期过期 | 默认不设置；发生泄漏/重置/安全事件时强制修改 |
| 临时密码 | 安全随机生成，24 小时后失效，首次登录必须修改 |
| 忘记密码 | 不提供公开自助接口，由管理员按 Q04 规则重置 |

### 2.3 登录失败与验证码

- 延续 Q04 锁定规则：连续失败 5 次锁定 30 分钟。
- 同一账号或来源 IP 在 **10 分钟内连续失败 3 次**后，后续登录必须完成验证码。
- 用户名不存在时也按来源 IP 触发相同规则（防账号枚举）。
- 验证码通过后仍须校验密码，不能解除已生效的账号锁定。
- **Nginx 和应用同时限制登录请求频率**。
- 失败次数和时间窗口均作为环境配置项。

### 2.4 MFA（多因素认证）

- 一期对**全部管理账号强制启用**基于标准验证器应用的 TOTP MFA。
- 不使用短信或邮件验证码。
- 管理员首次完成密码修改后**必须绑定 TOTP**；绑定完成前只能访问账号安全设置。
- TOTP 密钥**加密保存**，只在绑定时展示一次。
- 每个账号生成 **8 个一次性恢复码**，只展示一次并以哈希形式保存。
- 一期**不提供"记住此设备"**，每次重新登录均须完成 MFA。
- 同一个 TOTP 动态码在有效窗口内只能使用一次。
- MFA 连续失败同样计入登录安全限制。
- MFA 只能由**超级管理员重置**；重置后立即撤销全部会话，要求下次登录重新绑定。
- 最后一个超级管理员同时丢失 MFA 和恢复码时，只允许通过**服务器上的一次性应急命令**重置，并必须记录安全审计。
- 后续接入 SSO 时是否使用身份提供方 MFA 代替本地 TOTP，在实际接入时单独确认。

### 2.5 管理会话

#### 会话创建与存储

- 登录成功并完成 MFA 后，后端生成至少 **256 位安全随机会话 ID**。
- 会话保存在**所有 ToolHive 实例共享的服务端存储**中，不能只保存在单个应用进程。
- 共享会话存储不可用时**拒绝访问**，不能退回本地进程会话。

#### Cookie 安全

- 浏览器只保存会话 Cookie，必须设置：
  - `HttpOnly`
  - `Secure`
  - `SameSite=Lax`
- 不得设置宽泛的父域作用范围。
- 不得将登录 Token 保存到 `localStorage`。

#### 会话超时

- 默认**连续 30 分钟无操作后失效**。
- 单次登录**最长有效 8 小时**。
- 一期不提供"记住我"。
- 时长均允许通过环境配置调整。

#### 互斥登录

- 管理账号采用**互斥登录**，同一账号任意时刻只允许一个有效管理会话。
- 本地登录和后续 SSO 登录均遵守相同规则。
- 新登录在密码和 MFA 全部验证成功后，**原子方式撤销旧会话并激活新会话**。
- 并发登录时必须保证最终只保留一个有效会话，旧会话下一次请求立即返回未认证。
- 管理员可查看当前会话的登录时间、来源 IP 和最近活动时间。
- 超级管理员可对其他账号执行强制下线。

### 2.6 会话撤销触发条件

以下情况**立即撤销**该账号的有效会话：

- 账号被禁用或进行离职处理
- 管理员重置密码
- MFA 被重置
- 执行强制下线

用户主动修改自己密码时，重新生成当前会话 ID（互斥登录下不再保留其他旧会话）。

后台角色或管理操作项变化时**不强制退出**，但下一次请求必须立即依据最新配置校验。

登出时**服务端立即删除会话**，不能只清除浏览器 Cookie。

### 2.7 CSRF 与敏感信息保护

- 所有非只读请求（新增、修改、删除、审核、发布等）必须校验 **CSRF Token**。
- 检查 `Origin` 或 `Referer` 是否来自允许的管理前端。
- 以下时机**重新生成会话 ID**（防会话固定攻击）：
  - 登录成功
  - MFA 完成
  - 权限提升
  - 密码修改
- 会话 ID、密码、TOTP 密钥和恢复码**不得写入日志**。

### 2.8 SSO 预留

> 一期不实际接入 SSO，仅做架构预留。

- 管理账号增加可空且唯一的 `external_user_id` 字段，用于保存工号或外部系统唯一标识。
- 不建立独立的外部身份表，不支持一个管理账号绑定多个外部身份。
- 后续接入 SSO 时，适配器完成外部认证后返回唯一人员标识，ToolHive 用其匹配 `external_user_id`。
- 匹配不到内部账号时**拒绝登录**，不自动创建或绑定。
- 匹配成功后仍须检查内部账号状态和后台角色授权。
- SSO 只负责确认身份，不自动同步外部组织/部门/角色。
- 后续接入 SSO 后仍至少保留**一个本地超级管理员**作为故障应急入口。

## 模块三：后台角色与操作权限

> 来源：Q06、Q07

### 3.1 权限模型

- 管理账号与后台角色为**多对多**关系。
- 后台角色与管理操作项为**多对多**关系。
- 一个账号最终可执行的管理操作 = 其全部后台角色所含管理操作项的**并集**。
- 采用**默认拒绝原则**；一期只支持允许项，不引入显式拒绝和角色继承。
- 登录、退出、查看本人信息、修改本人密码属于**账号基础能力**，不要求分配后台角色。

### 3.2 管理操作项规范

- 统一称为"**管理操作项**"，每项使用稳定且唯一的操作码。
- 命名规范：**`管理对象:操作`**，例如：
  - `admin_account:view`
  - `role:assign`
  - `tool:review`
  - `tool:publish`
- 显示名称可以修改，但**已发布的操作码不得修改、删除或复用于其他功能**；废弃时标记为停用。
- 管理操作项**由代码定义**，不能由管理员在管理页面中任意创建。
- 新增操作项时必须同时完成：
  - 后端操作码声明
  - 管理 API 校验
  - 前端菜单或按钮关联
  - 启动或数据库升级时的目录同步
- 新增操作项默认**只对超级管理员生效**，不自动授予已有普通角色。
- 管理前端依据操作项控制菜单/页面/按钮展示；管理后端使用相同操作码**强制校验**。
- 前端隐藏**不能替代**后端安全校验。
- 未登录访问受控管理 API → **未认证**；已登录但缺少操作项 → **无权操作**。
- 一期只实现操作级控制，不增加按部门/人员/数据行划分的数据范围。

### 3.3 超级管理员角色

- 系统**内置、不可删除、不可修改**的超级管理员角色。
- 自动拥有当前及以后新增的**全部有效管理操作项**。
- 只有超级管理员可以**授予或移除**超级管理员角色。
- 不允许移除**最后一个启用状态超级管理员**的超级管理员角色。
- 普通管理员不能授予自己不具备的管理操作项，也不能修改超级管理员账号和角色。

### 3.4 普通后台角色

- 可由具备相应管理能力的管理员**创建、修改、启用、停用、归档**和分配管理操作项。
- 角色**不进行物理删除**，以保留历史审计关系。
- 以下变更**立即生效**，不要求账号重新登录：
  - 普通角色停用
  - 角色从账号移除
  - 管理操作项被撤销
- 会话只保存账号身份，**不永久固化**角色和管理操作项快照。

### 3.5 管理与工具运行控制边界

> 两套控制体系的关键隔离规则

| 维度 | 管理侧控制 | 工具运行侧控制 |
|------|-----------|---------------|
| 主体 | 管理账号 | 调用系统 + 业务身份 |
| 对象 | 后台页面和管理 API | 可发现和执行的工具 |
| 凭据 | 管理登录会话 | `system_id` + 运行接口认证凭据 |
| 载体 | 后台角色 → 管理操作项 | 调用系统 → 能力包 → 工具调用范围 |
| 命名 | "后台角色" / "管理操作项" | "工具调用控制" / "工具调用范围" |

核心原则：

- 管理账号凭据**只能**访问管理侧 API，调用系统凭据**只能**访问工具运行侧 API。
- 后台角色不能直接关联工具或能力包。
- 工具调用范围不能赋予访问管理页面或管理 API 的能力。
- 两套体系共享工具目录、能力包和调用系统等业务数据，但身份凭据、数据关系和校验结果**必须相互隔离**。
- 超级管理员自动拥有全部管理操作项，但**不自动获得任何工具调用范围**。
- 超级管理员如需实际调用工具，仍必须使用已登记的调用系统身份，通过完整的运行接口校验。
- 后续管理后台若增加工具测试执行功能，应使用**专门的测试调用身份**并记录审计，不允许超级管理员直接绕过工具运行侧校验。

## 模块四：调用系统管理

> 来源：Q08

### 4.1 调用系统定义

- "调用系统" = 调用 ToolHive 运行接口的**外部软件系统**，不是管理账号或最终业务用户。
- 按 **"一个外部项目 + 一个运行环境"** 的粒度登记。
- 同一外部项目的**开发环境和生产环境必须分别登记**，使用不同的 `system_id`、认证凭据、来源 IP 规则和工具调用范围。
- 同一环境内的多个服务实例**可以共用**一条调用系统记录；需要独立停用/审计/不同调用范围时分别登记。

### 4.2 system_id 规则

- 由 ToolHive **自动生成**，采用带 `sys_` 前缀的 UUID 或同类无业务含义全局唯一标识。
- 不允许管理员手工填写。
- 创建后**永久不变**，注销后也不得重新分配。
- `system_id` 只是公开的调用系统标识，**不能单独作为身份认证凭据**。

### 4.3 主记录字段

调用系统主记录至少包含：

- 系统名称（可修改，用于管理展示和审计阅读）
- 系统说明
- 所属环境（开发/生产）
- 所属部门或团队
- 主要负责人
- 联系方式
- 当前状态
- 可选生效时间和失效时间
- 创建和修改信息
- 停用或注销原因

### 4.4 生命周期状态

| 状态 | 说明 |
|------|------|
| 草稿 | 可配置各项参数，但不能调用运行接口 |
| 已启用 | 允许正常发起调用 |
| 已停用 | 立即拒绝全部运行接口请求，保留配置，可重新启用 |
| 已过期 | 超过失效时间后自动判断，拒绝请求；延长有效期后可恢复 |
| 已注销 | 永久停止使用，立即撤销全部认证凭据，不可重新启用，`system_id` 永不复用 |

- **不进行物理删除**，保留历史调用记录和管理审计关系。
- 状态变更**必须立即对运行接口生效**，不等待缓存过期。

### 4.5 启用前置条件

调用系统启用前必须具备：

- 明确的环境和负责人
- 有效身份认证凭据
- 来源 IP 规则
- 允许运行 API 范围
- 至少一个能力包或明确的工具调用范围
- 设置有效期时，当前时间必须处于有效期内

新建调用系统默认**没有任何工具调用范围**，启用状态也不表示自动获得全部工具。

### 4.6 有效期规则

- 调用系统本身的生效和失效时间**可以为空**。
- 长期正式业务系统可以不设置失效时间。
- 临时联调、临时项目或外部合作调用方**必须设置失效时间**。
- 调用系统长期有效**不代表认证凭据永久有效**，凭据应设置独立有效期并按 Q11 规则轮换。

### 4.7 关联配置（独立维护）

以下配置作为调用系统的关联配置维护，不直接固化在主记录中：

- 来源 IP 规则 → 留到 Q10 确认
- 身份凭据、请求签名和密钥生命周期 → 留到 Q11 确认
- 运行 API 范围和流量限制 → 留到 Q13 确认
- 工具调用范围 → 留到 Q15 确认

### 4.8 操作审计

- 创建、启用、停用、恢复和注销操作均记录操作人、时间和原因。
- 具体审计字段和留存规则 → 留到 Q23 确认。
- 临时维护、异常流量或疑似凭据泄漏时使用**停用**；系统永久下线时使用**注销**。

## 模块五：网络安全与入口架构

> 来源：M01

### 5.1 访问架构

- 一期管理前端和管理侧 API 允许通过**公网 HTTPS** 访问，不强制连接内网或 VPN。
- 生产访问链路：

  ```
  管理员浏览器 → 公网 HTTPS → Nginx → 管理前端 或 管理侧 API → ToolHive 后端
  ```

- **只开放 Nginx 的 HTTPS 入口**，ToolHive 后端应用端口不得直接暴露到公网。

### 5.2 Nginx 路由规则

三类路径由 Nginx 独立路由：

| 路径前缀 | 用途 | 访问策略 |
|----------|------|----------|
| `/admin/**` | 管理前端静态资源和页面路由 | 公网 |
| `/api/admin/**` | 管理侧 API | 公网 |
| `/api/runtime/**` | 工具运行侧 API | 仅内网 |

- 工具运行侧路径的公网请求由 Nginx **直接拒绝**，不转发给 ToolHive。
- 管理前端与管理 API 一期默认使用**同一域名**，避免跨域、Cookie 和 CORS 配置问题。

### 5.3 HTTPS 与 TLS

- 生产环境 HTTP 请求**自动跳转 HTTPS**。
- 只启用 **TLS 1.2 和 TLS 1.3**。
- 使用浏览器能够正常信任的证书。

### 5.4 安全 Header

Nginx 必须配置：

- **HSTS**（HTTP Strict Transport Security）
- 禁止页面被其他网站嵌入（`X-Frame-Options` / `Content-Security-Policy: frame-ancestors`）
- 禁止 MIME 类型猜测（`X-Content-Type-Options: nosniff`）
- 覆盖或清理不可信的代理 Header

### 5.5 访问控制

- 一期默认**不对每个管理员强制配置来源 IP 白名单**。
- Nginx 保留**可选的管理侧 IP 或网段限制**能力（公司出口、VPN 网段、安全事件临时收紧）。
- 管理侧来源限制与调用系统的来源 IP 白名单**相互独立**。

### 5.6 CORS

- 管理 API 默认**不开放跨域**。
- 后续前后端确需分域部署时，只允许部署配置中明确列出的来源。

### 5.7 限流

- Nginx 对管理登录接口增加**按来源的基础请求限流**。
- 应用层继续执行 Q04/M02 的账号锁定、禁用、会话撤销和登录失败规则。

### 5.8 部署配置

- 管理前端地址和管理 API 地址通过**部署配置**提供，不在前端代码中写死服务器 IP。
- 后续独立部署管理前端或接入 SSO 时，不改变管理 API、Nginx 路由和后台角色模型。

## 模块依赖关系

```
模块五（网络）
    ↓ 承载
模块二（认证）←──── 模块一（账号）
    ↓ 授权判断          ↓ 管理对象
模块三（权限）──────────────────┘
    ↓ 配置管控
模块四（调用系统）
```

- **模块五**是最底层，所有请求都经过 Nginx 路由和 HTTPS。
- **模块一**提供管理账号数据，是模块二和模块三的基础。
- **模块二**负责身份认证，认证通过后才能进入模块三的权限校验。
- **模块三**决定管理员能做什么操作，包括管理模块四中的调用系统。
- **模块四**是模块三的管理对象之一，由具备相应操作项的管理员配置和维护。

## 模块与 API 路径对应

| 模块 | 主要 API 路径 | 说明 |
|------|--------------|------|
| 模块一（账号） | `/api/admin/accounts/**` | 管理账号 CRUD、状态控制 |
| 模块二（认证） | `/api/admin/auth/**` | 登录、登出、MFA、密码修改、会话管理 |
| 模块三（权限） | `/api/admin/roles/**`、`/api/admin/operations/**` | 角色管理、操作项查询 |
| 模块四（调用系统） | `/api/admin/caller-systems/**` | 调用系统登记与生命周期 |
| 模块五（网络） | Nginx 配置层 | 路由、HTTPS、安全 Header、限流 |

# 一期上半部分（管理侧）实现审查问题清单

> 审查日期：2026-08-11  
> 审查范围：`tool-hive/` 后端、`frontend/` 管理前端及相关部署资料  
> 需求基准：`需求确认记录.md` 中已确认的 Q04、Q05、Q06、Q07、Q08、M01、M02，以及 `一期上半部分-功能模块拆分.md`  
> 当前状态：待修复，不具备一期上半部分验收条件

## 1. 审查结论

当前项目的总体架构方向与已确认方案基本一致：

- 使用同一套 ToolHive 后端承载管理侧能力，并为后续运行侧 API 预留独立路由空间。
- 管理前端作为独立工程，通过 `/api/admin/**` 访问管理侧 API。
- 已建立管理账号、后台角色、管理操作项、调用系统、公钥和来源 IP 等基础模型。
- 已使用 Argon2id、TOTP、Redis 服务端会话、CSRF Token 等安全组件。

但是当前实现仍属于可继续开发的功能骨架，尚未形成可验收的管理侧闭环。最主要的阻断点是：

1. 密码、临时密码、MFA 和完整会话之间的登录状态机无法闭环。
2. 管理操作项只完成了模型和枚举，所有管理 API 均未执行操作项校验。
3. 没有数据库迁移、首次超级管理员初始化命令和启动同步流程，空环境无法完成部署初始化。
4. 超级管理员保护、账号互斥登录和登录失败锁定均存在实际失效问题。
5. 管理前端缺少多项已确认页面和操作闭环，且无法按约定部署到 `/admin/**`。
6. Nginx、HTTPS、安全 Header、可信代理及生产密钥校验等网络和部署能力尚未落地。

## 4. P0 验收阻断问题

### P0-01：密码登录与 MFA 之间缺少受限的登录前置上下文

**现状**

- `AuthService.login_password()` 在密码正确后只返回 `require_mfa_setup` 或 `require_mfa`。
- 该步骤没有创建仅用于修改密码、绑定 MFA 或验证 MFA 的短期登录前置凭据。
- `/auth/login/verify-mfa` 和 `/auth/mfa/bind` 却依赖 `_get_current_user`，要求已经存在完整管理会话。
- 密码登录路由检查的是 API Schema `LoginResponse`，服务实际定义的是 `LoginResult`，服务和路由返回类型不一致。

**代码位置**

- `tool-hive/src/toolhive/services/auth_service.py:51`
- `tool-hive/src/toolhive/services/auth_service.py:99`
- `tool-hive/src/toolhive/api/admin/auth/router.py:99`
- `tool-hive/src/toolhive/api/admin/auth/router.py:106`
- `tool-hive/src/toolhive/api/admin/auth/router.py:203`

**影响**

- 新账号无法完成首次 MFA 绑定。
- 已绑定 MFA 的账号无法完成普通 MFA 登录。
- 在手工写入 MFA 数据前，正常登录主链路不可用。

**修复要求**

- 建立服务端保存的短期 `pre_auth` 登录前置上下文，至少绑定账号、当前阶段、来源信息、过期时间和一次性随机标识。
- 前置上下文只能访问当前允许的账号安全接口，不能访问其他管理 API。
- 完成密码修改和 MFA 后才创建完整管理会话。
- 统一 Service、Schema 和 Router 的返回类型，避免 ORM 账号对象被意外序列化。

### P0-02：临时密码有效期和首次强制修改规则未执行

**现状**

- 模型保存了 `must_change_password` 和 `temp_password_expires_at`。
- 登录服务没有读取或校验这两个字段。
- 当前流程在临时密码正确后直接进入 MFA 绑定或验证，没有执行“先修改密码，再绑定 MFA”。
- 管理员重置密码后同样无法保证用户先修改临时密码。

**代码位置**

- `tool-hive/src/toolhive/models/management_account.py:38`
- `tool-hive/src/toolhive/services/account_service.py:83`
- `tool-hive/src/toolhive/services/account_service.py:136`
- `tool-hive/src/toolhive/services/auth_service.py:51`

**影响**

- 24 小时临时密码失效规则实际无效。
- 临时密码可以长期作为正常密码使用。
- 登录安全流程不符合 M02 已确认顺序。

**修复要求**

- 密码校验后首先判断临时密码是否过期。
- `must_change_password=true` 时只允许访问受限的首次修改密码接口。
- 修改成功后轮转前置凭据，再进入 MFA 绑定或验证阶段。

### P0-03：登录失败次数和账号锁定不会持久化

**现状**

- 错误密码会增加 `login_failures` 并执行 `flush()`。
- 服务随后抛出 `AuthenticationError`，路由转换为 `HTTPException`。
- `get_db()` 对任何异常执行数据库回滚，因此失败次数和锁定状态最终不会提交。

**代码位置**

- `tool-hive/src/toolhive/services/account_service.py:205`
- `tool-hive/src/toolhive/services/auth_service.py:80`
- `tool-hive/src/toolhive/api/admin/auth/router.py:96`
- `tool-hive/src/toolhive/infrastructure/database.py:25`

**影响**

- “连续失败 5 次锁定 30 分钟”的数据库规则实际失效。
- MFA 失败所触发的账号失败计数也会被回滚。
- Redis 验证码计数和数据库账号计数出现不一致。

**修复要求**

- 将安全失败计数放入独立事务，或调整异常和事务边界，保证返回认证失败时计数仍能提交。
- 增加真实数据库集成测试，验证第 5 次失败后账号状态和锁定时间已经持久化。

### P0-04：验证码只有触发逻辑，没有验证闭环

**现状**

- Redis 会在账号或来源 IP 失败 3 次后返回 `captcha_required`。
- 登录请求 Schema 没有验证码字段或验证码凭据字段。
- 后端没有验证码生成、校验和一次性消费服务。
- 前端收到该错误后仅提示“需要验证码，请稍后重试”。

**代码位置**

- `tool-hive/src/toolhive/services/security/rate_limit.py:15`
- `tool-hive/src/toolhive/services/auth_service.py:74`
- `tool-hive/src/toolhive/api/admin/auth/schemas.py:8`
- `frontend/src/pages/LoginPage.tsx:47`

**影响**

- 达到阈值后，即使密码正确也无法登录，只能等待 Redis 计数自然过期。
- 实际行为变成固定时间锁定，不是已确认的验证码流程。

**修复要求**

- 明确验证码实现方案和验证凭据格式。
- 验证码成功后仍继续校验密码，且不能解除已经生效的账号锁定。
- 验证码凭据必须短期、一次性、绑定来源，并防止重放。

### P0-09：账号互斥登录不是原子操作

**现状**

- 文件定义了互斥登录 Lua 脚本，但实际没有执行。
- 当前流程采用 `GET 旧会话 → DELETE 旧会话 → pipeline 写新会话`。
- 两个并发登录可能分别写入两个有效会话哈希。
- `get_session()` 只检查会话哈希，不校验账号索引是否仍指向当前会话。
- `revoke_session()` 会无条件删除账号会话索引，旧会话撤销时可能误删新会话索引。
- 一旦产生孤立会话，`revoke_all_sessions()` 也只能撤销索引中记录的一条会话。

**代码位置**

- `tool-hive/src/toolhive/services/security/session.py:33`
- `tool-hive/src/toolhive/services/security/session.py:60`
- `tool-hive/src/toolhive/services/security/session.py:87`
- `tool-hive/src/toolhive/services/security/session.py:103`
- `tool-hive/src/toolhive/services/security/session.py:148`

**影响**

- 不满足“同一账号任意时刻只有一个有效会话”的已确认要求。
- 并发登录、密码重置、强制下线和禁用账号后可能残留有效旧会话。

**修复要求**

- 使用经过验证的 Lua 脚本或 Redis 事务实现原子替换。
- 读取会话时校验账号索引仍指向当前会话。
- 删除索引时使用 compare-and-delete，不能删除已经指向其他会话的索引。
- 增加真实 Redis 并发测试。

## 5. P1 功能与安全问题

### P1-01：密码历史保存对象错误

- `_set_password()` 把新密码哈希写入历史，然后再把同一新密码写入账号。
- 正确逻辑应在替换前保存旧密码哈希，并同时检查当前密码和历史密码。
- 当前实现可能允许 `A → B → A`，管理员重置密码也没有正确进入历史链路。
- 代码位置：`tool-hive/src/toolhive/services/account_service.py:225`。

### P1-02：TOTP 动态码可以在同一有效窗口重复使用

- MFA 模型没有保存最后一次成功使用的 TOTP 时间窗口或计数器。
- `verify_totp()` 只验证当前及前后窗口，不检查该窗口是否已经被账号使用。
- 不符合“同一个动态码在有效时间窗口内只能使用一次”的要求。
- 代码位置：`tool-hive/src/toolhive/services/security/totp.py:59`、`tool-hive/src/toolhive/models/mfa_config.py:13`。

### P1-03：恢复码消费存在并发重复使用风险

- 恢复码通过读取 JSON、从列表移除再写回的方式消费。
- 两个并发事务可能都读取到同一恢复码并同时验证成功。
- 应使用行锁、版本号或数据库条件更新保证一次性消费。
- 代码位置：`tool-hive/src/toolhive/models/mfa_config.py:43`。

### P1-04：MFA 重置和应急恢复能力缺失

- 没有超级管理员重置其他账号 MFA 的 API 和页面。
- 没有最后一个超级管理员的服务器一次性应急重置命令。
- MFA 重置后的强制下线和重新绑定流程没有实现。
- 应急操作所要求的安全审计也不存在。

### P1-05：生产环境允许使用固定开发密钥

- `totp_encryption_key` 和 `csrf_secret` 为空时不会拒绝启动。
- TOTP 和 CSRF 会分别回退到代码内固定开发密钥。
- `.env.example` 同时提示安全参数可以保留默认值，容易造成错误部署。
- 代码位置：`tool-hive/src/toolhive/services/security/totp.py:89`、`tool-hive/src/toolhive/services/security/csrf.py:12`、`tool-hive/.env.example:28`。

### P1-06：CSRF 未检查 Origin 或 Referer

- 中间件注释声明会校验来源，但实现只检查 `X-CSRF-Token`。
- 未配置允许的管理前端来源列表。
- 不符合 M02 对非只读请求的双重校验要求。
- 代码位置：`tool-hive/src/toolhive/api/admin/middleware.py:52`。

### P1-07：来源 IP 直接信任客户端 X-Forwarded-For

- 登录、MFA、恢复码和修改密码接口直接读取任意客户端传入的 `X-Forwarded-For`。
- 没有可信代理 IP/网段配置，也没有解析代理链。
- 没有 Nginx Header 覆盖配置时，调用者可以伪造 IP 绕过来源计数和限流。
- 代码位置：`tool-hive/src/toolhive/api/admin/auth/router.py:90`。

### P1-08：修改密码后的会话和 CSRF 交接不完整

- 修改密码路由先注销旧会话，再对已经删除的旧会话调用 `rotate_session_id()`。
- 随后又重新创建一条新会话，前面的轮转结果未使用。
- 新会话对应的 CSRF Token 没有返回，前端仍保存旧会话的 CSRF Token。
- 修改密码后的下一次非只读请求可能直接返回 CSRF 失败。
- 代码位置：`tool-hive/src/toolhive/api/admin/auth/router.py:224`。

### P1-09：会话保存超级管理员快照且当前账号状态未再次校验

- 会话中保存了 `is_super_admin`，角色变化后该值不会立即更新。
- 会话信息接口和前端可能继续展示旧的超级管理员状态。
- `_get_current_user()` 只确认账号存在，没有再次检查账号是否仍为启用状态。
- 与“会话只保存账号身份，角色和操作项变化下一次请求立即生效”的要求不完全一致。
- 代码位置：`tool-hive/src/toolhive/services/security/session.py:16`、`tool-hive/src/toolhive/api/admin/auth/router.py:54`。

### P1-10：SSO 扩展只预留了字段，没有统一接入层

## 2. 部署步骤

### 步骤 1：建立数据库通道

PostgreSQL 只监听服务器本地，**所有数据库操作前必须先建隧道**。

```powershell
# 开一个独立窗口（或后台任务）执行，保持运行
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 `
    -L 5432:127.0.0.1:5432 root@132.232.176.80 -p 22

# 另开一个窗口验证
Test-NetConnection 127.0.0.1 -Port 5432
```

**验收**：`Test-NetConnection` 返回 `TcpTestSucceeded : True`。

> **排障**：若应用报 `ConnectionRefusedError`，第一件事就是确认隧道还活着。
> 隧道是前台进程，窗口关掉就断了。

---

### 步骤 2：PostgreSQL 安装 `pg_trgm`

**这是本次部署唯一的「缺件」**。服务器当前只装了 PostgreSQL 本体，没有装 contrib 包。
实测 `pg_available_extensions` 里只有 `plpgsql` 和 `vector` 两项，`pg_trgm` 不在其中。

而 M0 的关键词检索路径（设计 §6.2）依赖 `pg_trgm` 提供 `gin_trgm_ops` 索引操作符类，
所以**必须在服务器上补装 contrib 包**。

**在服务器上执行**（SSH 登录 `root@132.232.176.80`）：

```bash
# 1) 先确认实际安装的包名与大版本
rpm -qa | grep -i postgresql

# 2) 安装 contrib（OpenCloudOS / RHEL 系，按上一步的实际大版本选择）
sudo dnf install -y postgresql15-contrib

# 若提示「无此包」，按顺序尝试：
#   sudo dnf install -y postgresql-contrib
# 若仓库里都没有，需配置 PGDG 源，或从对应版本的安装介质中提取

# 3) 无需重启 PostgreSQL —— pg_trgm 不需要进 shared_preload_libraries
```

**验收**（装完立即在数据库里查，不需要重启服务）：

```sql
-- 期望返回一行：pg_trgm | <版本> |
SELECT name, default_version FROM pg_available_extensions WHERE name = 'pg_trgm';
```

> ⚠️ **两个常见误解**：
> 1. **装包 ≠ 可用。** `CREATE EXTENSION` 是**按库生效**的。装好包后，仍要在**每个**用到它的库里
>    各执行一次 `CREATE EXTENSION pg_trgm`（M0 就是 `toolhive` 库，见步骤 3）。
> 2. **`pg_trgm` 不需要重启数据库。** 只有 `shared_preload_libraries` 类扩展才需要重启。

---

### 步骤 3：初始化 `toolhive` 数据库

`toolhive` 库**已存在且为空**（实测 0 张表，仅 `plpgsql`），因此**不需要 `CREATE DATABASE`**，
直接装扩展 + 建表即可。**不要 `DROP DATABASE`。**

**① 装扩展**

```sql
CREATE EXTENSION IF NOT EXISTS vector;    -- 服务器已提供 0.8.6；halfvec 需 pgvector >= 0.7
CREATE EXTENSION IF NOT EXISTS pg_trgm;   -- 依赖步骤 2 装好的 contrib 包
```

**② 校验扩展**

```sql
SELECT extname, extversion FROM pg_extension ORDER BY extname;
-- 期望三行：plpgsql / pg_trgm / vector
```

**③ 建表**

执行 `03-表结构DDL-v0.2.md` §3 的完整 DDL。该 DDL 可整体一次性执行，已实测通过
（16 张表、约束、外键、索引全部创建成功）。

**④ 校验不变量**

```sql
-- ① 16 张表全部存在
SELECT count(*) FROM pg_tables WHERE schemaname = 'public';
-- 期望：16

-- ② index_meta 的「单活索引」唯一约束生效
SELECT indexname, indexdef FROM pg_indexes
WHERE tablename = 'index_meta' AND indexdef ILIKE '%UNIQUE%';
-- 期望：至少一行，且唯一约束覆盖 active 标志

-- ③ halfvec 与余弦距离可用（DDL 中 tool_embedding 用的就是这个类型）
SELECT '[1,0,0]'::halfvec(3) <=> '[0,1,0]'::halfvec(3) AS cosine_distance;
-- 期望：1.000（两个正交向量）
```

**验收**：表数量 = 16，且 `halfvec` 查询返回 `1.000`。

> **关于 `halfvec`**：`tool_embedding.embedding` 使用 `halfvec(2560)`。
> 这是必需的 —— PostgreSQL 的 HNSW 索引对 `vector` 类型的**维数上限是 2000**，
> 2560 维无法直接用 `vector` 建 HNSW 索引（实测报错 `column cannot have more than 2000 dimensions for hnsw index`）。
> `halfvec`（float16 存储）绕开该限制，实测可正常建索引并正确返回最近邻。
> 代价是 float16 相对 float32 有轻微精度损失，由检索质量评测（任务 K2，`recall@30 ≥ 0.95`）把关。

### 步骤 4：PostgreSQL 参数

实测当前参数（**这些是服务器全局值，部署时建议只改数据库级，不动全局**）：

| 参数 | 当前实测值 | 部署建议 | 理由 |
|---|---|---|---|
| `statement_timeout` | `0`（永不超时） | **数据库级设为 `5s`** | 只有 97 个可用连接（`max_connections=100` 减 3 保留）。一条走错计划的查询会永久占住连接，拖垮检索路径 |
| `idle_in_transaction_session_timeout` | `0` | **数据库级设为 `30s`** | 防连接泄漏在事务里长期持有锁与快照 |
| `shared_buffers` | `128 MB` | M0 无需调整 | 1w 工具向量约 50 MB 裸数据；M1 工具量上来后再评估 |
| `maintenance_work_mem` | `64 MB` | 建 HNSW 索引的会话临时设 `512MB` | HNSW 构建内存密集，内存不足会显著变慢 |
| `max_connections` | `100` | 应用侧连接池 `pool_size ≤ 20` | 共享服务器，不要吃满连接数 |
| `work_mem` | `4 MB` | 无需调整 | 检索查询不重 |
| `effective_cache_size` | `4 GB` | 无需调整 | — |

**设置命令**（数据库级，不影响服务器上其它库，重连后生效）：

```sql
ALTER DATABASE toolhive SET statement_timeout = '5s';
ALTER DATABASE toolhive SET idle_in_transaction_session_timeout = '30s';

-- 校验
SELECT datname, unnest(setconfig) FROM pg_db_role_setting s
JOIN pg_database d ON d.oid = s.setdatabase;
```

**验收**：重连后 `SHOW statement_timeout;` 返回 `5s`。

> ⚠️ 注意：`ALTER DATABASE ... SET statement_timeout` 会让**所有**连到该库的会话继承，
> 包括将来跑数据迁移的会话。迁移脚本里需要显式 `SET LOCAL statement_timeout = 0`。

### 步骤 5：Redis 准备

**① 分配 DB 编号**

`db0` 已被服务器上另一个应用占用，**ToolHive 用 `db1`**（实测为空）。
这一步不需要在 Redis 上执行任何命令，只要在应用的连接串里写对编号即可：

```
redis://:Hejinxuan010859@132.232.176.80:6379/1
```

**② 确认 `db1` 未被占用**

```powershell
F:\soft\anaconda\envs\toolhive\python.exe -c "import redis; r=redis.from_url('redis://:Hejinxuan010859@132.232.176.80:6379/1'); print('dbsize =', r.dbsize())"
```

**验收**：`dbsize = 0`。

**③ 设置内存上限（Redis 运维侧，建议执行）**

实测当前 `maxmemory = 0`（不限制）、`maxmemory-policy = noeviction`。
M0 的幂等结果缓存 TTL 最长 24 小时、单条上限 256KB，在键量增长时**没有内存上限兜底**。

建议在 `redis.conf` 中设置上限：

```conf
maxmemory 512mb
maxmemory-policy noeviction
```

- **保留 `noeviction` 是对的**：幂等结果缓存若被静默淘汰，「同键重放返回同结果」的承诺就会失效；
  写失败至少是显式错误，能被发现。
- 但**应当有上限**，让写失败发生在可控范围内。
- 这是**建议项，不阻塞部署**。若这台 Redis 由其它团队运维，走变更流程提出即可。

> 修改 `maxmemory` 用 `CONFIG SET` 可热生效，但**建议同时写入 `redis.conf`**，否则重启后丢失。

**验收**：`CONFIG GET maxmemory` 返回非 `0`（若采纳本建议）。

## 5. 部署自检脚本

### 5.1 说明

本机**没有安装 `psql`，也没有安装 `redis-cli`**（实测均不在 PATH，常见安装目录也没有）。
因此自检使用纯 Python 脚本，依赖的都是步骤 6 中已确认装好的库。

> 若你更习惯 `psql` / `redis-cli`，可以在**服务器上**直接使用（那台机器上一定有）。

### 5.2 preflight 脚本

保存为 `scripts/preflight.py`（任务 A1 建立目录后放入）。

```python
"""ToolHive M0 部署自检。

用法（必须使用 conda 环境的解释器）：
    set TOOLHIVE_DATABASE_URL=postgresql://postgres:<PW>@127.0.0.1:5432/toolhive
    set TOOLHIVE_REDIS_URL=redis://:<PW>@132.232.176.80:6379/1
    set TOOLHIVE_EMBEDDING_API_KEY=<KEY>
    F:\\soft\\anaconda\\envs\\toolhive\\python.exe scripts\\preflight.py

退出码：0 = 无阻塞项；1 = 存在阻塞项。
"""
from __future__ import annotations

import asyncio
import os
import sys

sys.stdout.reconfigure(encoding="utf-8", errors="replace")

import asyncpg
import httpx
import redis.asyncio as aioredis

EXPECTED_EMBEDDING_DIM = 2560
EXPECTED_TABLE_COUNT = 16

BLOCKING: list[str] = []
WARNING: list[str] = []


def ok(msg: str) -> None:
    print(f"  [PASS] {msg}")


def warn(msg: str) -> None:
    print(f"  [WARN] {msg}")
    WARNING.append(msg)


def bad(msg: str) -> None:
    print(f"  [FAIL] {msg}")
    BLOCKING.append(msg)


async def check_postgres() -> None:
    print("\n== PostgreSQL ==")
    dsn = os.environ.get("TOOLHIVE_DATABASE_URL")
    if not dsn:
        bad("未设置 TOOLHIVE_DATABASE_URL")
        return

    try:
        conn = await asyncpg.connect(dsn, timeout=10)
    except Exception as exc:  # noqa: BLE001
        bad(f"连接失败：{type(exc).__name__}: {exc}")
        print("       若为 ConnectionRefusedError，先确认 SSH 隧道是否还在（步骤 1）")
        return

    try:
        version = str(await conn.fetchval("SELECT version()"))
        ok(f"连接成功：{version[:100]}")

        # 服务器是否提供所需扩展
        for name in ("vector", "pg_trgm"):
            row = await conn.fetchrow(
                "SELECT default_version FROM pg_available_extensions WHERE name = $1", name
            )
            if row:
                ok(f"服务器提供扩展 {name} (default {row['default_version']})")
            else:
                bad(f"服务器缺少扩展 {name} —— 见步骤 2（装 postgresql-contrib）")

        # 当前库是否已装
        installed = {r["extname"] for r in await conn.fetch("SELECT extname FROM pg_extension")}
        for name in ("vector", "pg_trgm"):
            if name in installed:
                ok(f"库内已安装 {name}")
            else:
                bad(f"库内未安装 {name} —— 执行 CREATE EXTENSION {name};（步骤 3）")

        # 表数量
        n = await conn.fetchval("SELECT count(*) FROM pg_tables WHERE schemaname = 'public'")
        if n == EXPECTED_TABLE_COUNT:
            ok(f"表数量 = {n}")
        else:
            bad(f"表数量 = {n}，期望 {EXPECTED_TABLE_COUNT} —— 执行 DDL 文档 §3（步骤 3）")

        # halfvec 与余弦距离
        if "vector" in installed:
            try:
                d = float(
                    await conn.fetchval("SELECT '[1,0,0]'::halfvec(3) <=> '[0,1,0]'::halfvec(3)")
                )
                if abs(d - 1.0) < 1e-3:
                    ok(f"halfvec 余弦距离可用（正交向量 = {d:.3f}）")
                else:
                    warn(f"halfvec 距离异常：期望 1.000，实得 {d}")
            except Exception as exc:  # noqa: BLE001
                bad(f"halfvec 不可用：{exc}")

        # index_meta 单活唯一约束
        if n == EXPECTED_TABLE_COUNT:
            row = await conn.fetchrow(
                "SELECT indexname FROM pg_indexes "
                "WHERE tablename = 'index_meta' AND indexdef ILIKE '%UNIQUE%' LIMIT 1"
            )
            if row:
                ok(f"index_meta 单活唯一约束存在（{row['indexname']}）")
            else:
                bad("index_meta 缺少 UNIQUE 约束 —— DDL 未正确执行")

        # 参数体检
        settings = {
            r["name"]: r["setting"]
            for r in await conn.fetch(
                "SELECT name, setting FROM pg_settings WHERE name IN "
                "('statement_timeout','idle_in_transaction_session_timeout')"
            )
        }
        if settings.get("statement_timeout") == "0":
            warn("statement_timeout = 0，建议按步骤 4 设为 5s")
        else:
            ok(f"statement_timeout = {settings.get('statement_timeout')}")
        if settings.get("idle_in_transaction_session_timeout") == "0":
            warn("idle_in_transaction_session_timeout = 0，建议按步骤 4 设为 30s")

        # 连接角色
        is_super = await conn.fetchval(
            "SELECT rolsuper FROM pg_roles WHERE rolname = current_user"
        )
        who = await conn.fetchval("SELECT current_user")
        if is_super:
            warn(f"当前以超级用户 {who} 连接，正式环境建议改用专用角色（§8）")
        else:
            ok(f"连接角色 {who} 非超级用户")
    finally:
        await conn.close()


async def check_redis() -> None:
    print("\n== Redis ==")
    url = os.environ.get("TOOLHIVE_REDIS_URL")
    if not url:
        bad("未设置 TOOLHIVE_REDIS_URL")
        return

    client = aioredis.from_url(url, socket_connect_timeout=10, decode_responses=True)
    try:
        await client.ping()
    except Exception as exc:  # noqa: BLE001
        bad(f"连接失败：{type(exc).__name__}: {exc}")
        await client.aclose()
        return

    try:
        ok(f"连接成功：{url.rsplit('@', 1)[-1]}")

        db = await client.dbsize()
        if db == 0:
            ok("目标 DB 为空，未被其它应用占用")
        else:
            bad(f"目标 DB 已有 {db} 个键 —— 可能被别的应用占用，换一个 DB 编号（步骤 5）")

        cfg = await client.config_get("maxmemory", "maxmemory-policy")
        if cfg.get("maxmemory") in (None, "0"):
            warn("maxmemory = 0（不限制），建议按步骤 5 设置上限")
        else:
            ok(f"maxmemory = {cfg['maxmemory']}，policy = {cfg.get('maxmemory-policy')}")
    finally:
        await client.aclose()


async def check_embedding() -> None:
    print("\n== Embedding 服务 ==")
    key = os.environ.get("TOOLHIVE_EMBEDDING_API_KEY")
    base = os.environ.get("TOOLHIVE_EMBEDDING_BASE_URL", "https://tokenhub.tencentmaas.com").rstrip("/")
    model = os.environ.get("TOOLHIVE_EMBEDDING_MODEL", "kinfra-text-embedding-4b")

    if not key:
        warn("未设置 TOOLHIVE_EMBEDDING_API_KEY，跳过（这是必需项，见 §1.4）")
        return

    try:
        async with httpx.AsyncClient(timeout=20) as c:
            r = await c.post(
                f"{base}/v1/embeddings",
                headers={"Authorization": f"Bearer {key}"},
                json={"model": model, "input": "ping"},
            )
        if r.status_code != 200:
            bad(f"HTTP {r.status_code}：{r.text[:200]}")
            return
        dim = len(r.json()["data"][0]["embedding"])
        if dim == EXPECTED_EMBEDDING_DIM:
            ok(f"{model} 返回 {dim} 维，与 DDL 的 halfvec({EXPECTED_EMBEDDING_DIM}) 一致")
        else:
            bad(f"维度 = {dim}，期望 {EXPECTED_EMBEDDING_DIM} —— DDL 必须同步修改！")
    except Exception as exc:  # noqa: BLE001
        bad(f"请求失败：{type(exc).__name__}: {exc}")


async def main() -> int:
    print("ToolHive M0 部署自检")
    print("=" * 60)
    await check_postgres()
    await check_redis()
    await check_embedding()

    print("\n" + "=" * 60)
    print(f"阻塞项 {len(BLOCKING)} 个 / 警告项 {len(WARNING)} 个")
    if BLOCKING:
        print("\n阻塞项（必须解决）：")
        for m in BLOCKING:
            print(f"  - {m}")
    if WARNING:
        print("\n警告项（建议处理，不阻塞）：")
        for m in WARNING:
            print(f"  - {m}")
    if not BLOCKING:
        print("\n✅ 无阻塞项，环境已就绪。")
    return 1 if BLOCKING else 0


if __name__ == "__main__":
    raise SystemExit(asyncio.run(main()))
```

## 6. 日常运维

### 6.1 隧道管理

隧道是前台进程，窗口关闭即断开。长期使用时建议：

- 用**独立的终端窗口**专门跑隧道，不要和业务命令混在一起；
- 或注册为 Windows 计划任务 / 用 `autossh` 类工具做自动重连；
- 应用启动前先确认隧道通，否则会得到 `ConnectionRefusedError`。

### 6.2 备份范围

| 对象 | 是否需要备份 | 说明 |
|---|---|---|
| PostgreSQL `toolhive` 库 | ✅ 必须 | 业务数据主体，含 `credential` 密文 |
| **KEK** | ✅ **必须，且单独备份** | **KEK 丢失 = 所有凭据密文永久无法解密** |
| Redis `db1` | ❌ 不需要 | 幂等结果缓存与限流计数，全部带 TTL，丢失可接受 |
| `.env` | ✅ 备份到密码库 | 含数据库密码与 Embedding Key |

### 6.3 停机顺序

应用 → 隧道。数据库与 Redis 是共享服务，**不随本项目停止**。

# ToolHive 一期下半待实现功能

> 文档版本：v1.0  
> 更新日期：2026-08-24  
> 文档目的：定义一期下半部分待实现的 Catalog 与工具应用运行链路范围，作为后续设计冻结、开发拆分和验收依据。  
> 范围说明：本文不重复列出一期上半已实现功能；已实现管理基础见 [一期上半已实现功能](./一期上半已实现功能.md)。

## 1. 阶段目标

一期下半部分要在现有管理基础上完成最小、可控的 HTTP 工具调用闭环。

```text
管理员维护 Catalog 并审核发布
  → 调用系统携带签名访问运行 API
  → 平台认证并计算当前可见、可执行工具
  → Provider 按固定映射调用外部 HTTP 接口
  → 返回标准化结果，记录 Trace 与审计
```

下半部分仍是同一个 ToolHive 应用的一部分：Catalog 管理沿用 `/api/admin/**` 和管理前端，工具应用模块只通过 `/api/runtime/v1/**` 面向调用系统提供服务，不新增独立运行后端或独立管理前端。

## 2. 已有前置能力

下半开发可直接复用一期上半已实现的下列能力：

- 调用系统、调用系统公钥、来源 IP 规则、运行策略、工具/能力包范围和系统级紧急禁用配置；
- 管理账号、角色、管理操作项、后端操作级鉴权与管理前端按钮级权限控制；
- PostgreSQL、Redis、Outbox、Chroma 配置对象、单 Worker 部署约束和网关入口校验；
- 基础管理审计、脱敏处理、管理员初始化和部署脚本。

下半开发必须将这些配置真正接入运行链路；仅有管理表和管理接口不代表运行 API 已具备对应控制能力。

## 4. Catalog 管理

Catalog 是运行 API 的配置前提，需要在现有管理端中完成以下能力。

| 子模块 | 待实现功能 |
|--------|------------|
| Provider | Provider 的创建、修改、启停、归档、目标安全配置和环境边界管理。 |
| 能力包 | 能力包的创建、修改、工具关联、调用系统授权关联和生命周期管理。 |
| 工具 | 工具编码、命名空间、描述、风险等级、输入输出 Schema、可发现性与可执行性管理。 |
| 工具版本 | 草稿版本、版本详情、默认版本、版本归档和发布切换规则。 |
| 执行绑定 | Provider 与工具版本的固定 HTTP 映射，包括方法、路径模板、参数映射、允许 Header 与响应处理。 |
| 审核与发布 | 送审、通过、驳回、发布、停用、撤回、归档、发布历史和状态变更记录。 |
| 管理界面 | Provider、能力包、工具、版本、执行绑定、审核与发布的管理页面及操作项控制。 |
| 索引任务 | Catalog 变更通过 Outbox 触发 Chroma 派生索引同步，并可查询失败与重试状态。 |

Catalog 中只能登记一期允许的固定 HTTP 映射。目标业务系统密码、API Key、OAuth Secret、客户端私钥、`credential_ref` 和 Secret Store 不属于一期范围。

## 5. 工具应用入口与调用系统认证

### 5.1 运行入口

- 建立并挂载 `/api/runtime/v1/**` 路由、服务和统一错误处理链。
- 将运行入口与管理入口使用不同的身份认证与访问控制链隔离。
- 运行 API 只面向内网调用系统；Nginx 与应用层共同处理入口标识、可信代理和来源 IP。
- 运行请求必须按调用系统已有的来源 IP 规则进行校验；`*` 规则不代表向公网开放。

### 5.2 调用系统签名认证

实现调用系统的请求认证中间件或等价组件，至少包括：

- 从请求中识别 `system_id` 和用于验签的有效公钥；
- RSA-PSS 请求签名验证，算法为 `RSA-PSS-SHA256`；
- HTTP 方法、完整版本路径、时间戳、Nonce、请求体摘要等 canonical 内容校验；
- 时间窗口校验、防重放 Nonce 共享存储与安全依赖不可用时默认拒绝；
- 调用系统生命周期、有效期、紧急禁用、公钥状态和密钥轮换的实时校验；
- 认证失败、签名无效、时间戳超窗、Nonce 重放、来源 IP 不匹配等明确错误语义和 Trace 记录。

## 6. 运行范围、流量控制与 ToolContext

### 6.1 运行范围接入

现有调用系统管理端已可以保存运行 API 范围、工具/能力包范围、QPS、并发、配额、超时、熔断和紧急禁用配置。下半需实现这些配置在运行请求中的实时生效：

- 按调用系统限制可访问的运行 API；
- 按调用系统及 Catalog 状态限制工具、能力包和命名空间范围；
- 实现 QPS、并发、日配额、请求超时和熔断控制；
- 紧急禁用、停用、注销、密钥撤销和范围变更必须立即影响后续运行请求；
- Catalog 落地后，对工具和能力包范围编码进行引用校验。

### 6.2 ToolContext

定义并实现运行请求中的 ToolContext 契约，包括：

- 用户、租户、角色、渠道、会话、请求来源和追踪信息；
- 每个字段的来源、可信等级、格式校验和缺失处理；
- 调用系统可以传递哪些业务身份字段，以及平台和外部业务系统各自承担的验证边界；
- Trace ID 的生成、透传和错误关联规则。

## 7. 工具调用控制

工具发现和工具执行都必须基于实时的工具调用控制结果，而不能只依赖调用系统认证成功。

- 计算调用系统、ToolContext、能力包、工具范围、策略、租户范围和有效期的最终允许集合。
- 默认拒绝：未配置、未授权、已停用、有效期失效、上下文不可信或安全依赖不可用时拒绝。
- 区分“可发现”与“可执行”：工具可被返回给调用方不代表当前参数一定允许执行。
- 对高风险工具或写操作增加确认申请、确认令牌、有效期、一次性消费和二次校验机制。
- 防止 Discover、Resolve 或错误消息泄露未授权工具的完整 Schema、目标地址或敏感策略信息。

## 8. 工具发现与执行 API

### 8.1 Resolve 与 Discover

| API | 待实现职责 |
|-----|------------|
| `POST /api/runtime/v1/tools/resolve` | 按工具 ID、工具编码或版本进行精确解析；不依赖 Chroma；返回通过范围与策略校验的工具 Schema。 |
| `POST /api/runtime/v1/tools/discover` | 按自然语言、ToolContext 和调用系统范围检索候选工具，返回受控候选、排序与覆盖度信息。 |

### 8.2 Execute 与确认

| API | 待实现职责 |
|-----|------------|
| `POST /api/runtime/v1/tools/{tool_code}/execute` | 二次授权、工具版本选择、JSON Schema 校验、参数级安全校验、幂等、Provider 调用、结果标准化和错误转换。 |
| `POST /api/runtime/v1/confirmations` | 高风险操作的确认申请、确认令牌校验、过期处理和防重放。 |

Execute 不能依赖 Discover 的旧结果，必须重新校验调用系统、ToolContext、工具状态、范围、策略、真实参数和确认状态。

## 9. HTTP Provider 与受控出站

一期只实现不需要 ToolHive 代持目标系统凭据的 HTTP Provider。

- 建立统一 `ProviderGateway`；管理 Controller、运行 Controller 和其他业务模块不得绕过它直接调用任意外部地址。
- 仅按已审核的固定映射生成请求；调用方和 LLM 不得决定 URL、HTTP 方法、认证 Header 或未声明参数。
- 校验目标域名、端口、路径、协议与 DNS 解析结果，防护 SSRF。
- 强制 HTTPS、证书校验与受控重定向策略；默认不自动跟随重定向。
- 限制请求体、响应体、Header 数量、连接时间、读取时间、总执行时间和执行并发。
- 区分读写工具的超时、幂等、重试和熔断规则；外部写入状态不明时不得盲目重试。
- 对 Provider 响应执行格式校验、大小限制、脱敏、标准化和错误转换。

## 10. 检索、索引与降级

- 使用 PostgreSQL 作为工具定义、发布状态、授权和版本的唯一事实来源。
- 使用嵌入式 Chroma 保存可从 PostgreSQL 重建的 Catalog 派生索引。
- 精确 Resolve 和按工具 ID/编码的查询不依赖 Chroma。
- 自然语言 Discover 优先使用 Chroma 与 Embedding 检索；临时不可用时降级为限制数量的 PostgreSQL 关键词检索。
- 无论主检索还是降级检索，候选都必须经过发布状态、调用系统范围和工具调用控制校验，不得扩大可见范围。
- 无法形成可靠候选时返回明确的检索暂不可用或无匹配结果，不得返回未授权信息。
- 通过 Outbox 保证 Catalog 变更到 Redis/Chroma 派生数据的投递、重试与失败处理。

## 11. Trace 与审计

一期下半需完成运行链路的基础可追溯性：

- 为运行请求生成或透传 `trace_id`，并在响应和错误中关联；
- 记录调用系统认证、来源 IP、签名、Nonce、运行范围、授权决策、检索、确认、执行和 Provider 结果的关键事实；
- 复用管理审计的脱敏原则，避免密码、Session、Nonce 原文、签名、私钥、目标敏感数据进入普通日志；
- 将管理变更与相关运行 Trace 建立可关联记录；
- 一期只实现基础 Trace 与管理变更基础审计，不包含审计查询/导出/报表、合规流程和留存策略管理界面。

## 12. 一期下半完成判定

下半完成应以以下受控闭环为准：

1. 管理员可以维护 Catalog，并完成审核和发布。
2. 已登记调用系统可以通过来源 IP、有效公钥签名、时间窗口和 Nonce 校验访问运行 API。
3. 平台可以基于调用系统和 ToolContext 返回允许发现的工具。
4. 平台可以在执行时进行二次授权、参数验证和高风险确认。
5. Provider 只能按审核后的固定映射调用首批外部 HTTP 接口。
6. 检索不可用时可以在不扩大授权范围的前提下受控降级。
7. 请求、认证、授权、检索、执行、Provider 调用和管理变更保留基础 Trace 或审计记录。
8. 管理侧与运行侧作为同一个 ToolHive 应用，具备一期范围内的初始化、网关、配置和基础验收交付物。

## 13. 一期明确不做

- 实际接入 SSO；
- MCP Provider、MCP Registry、平台 MCP 网关和 gRPC Provider；
- 工具执行的异步长任务、任务中心、取消、回调和死信治理；
- 高级灰度发布、自动回滚和复杂版本治理；
- 监控看板、报表、在线质量评估和成本评估；
- 多地域容灾、跨地域部署和大规模高可用；
- 目标业务系统凭据代持、Secret Store、`credential_ref` 与依赖目标凭据的 Provider 执行。

## 15. 补充记录（H10：签名算法多算法与验签器工厂）

> 本节仅追加补充记录，不修改上文内容。

### 2026-08-26

- 5.2 调用系统签名认证补充：算法注册表一期为 `RSA-PSS-SHA256`（必选）+ `Ed25519`（算法标识 `"Ed25519"`）；SM2-SM3 不纳入一期。
- RSA-PSS 协议参数冻结：PSS + MGF1(SHA256)，salt length 固定 32；RSA 公钥位长下限取 `RuntimeSecuritySettings.signing_key_min_bits`（默认 2048）。
- 验签器工厂：`runtime/authentication/verifiers/` 提供统一接口与注册表，按公钥记录 `algorithm` 分发，未知算法默认拒绝；每把公钥绑定单一算法，算法选择以 `key_id` 查到的公钥记录为准。
- 认证协议不变：一期、二期仅 `TOOLHIVE-SIGN-V1`，不引入 HMAC、mTLS、API Key、OAuth 等其他认证协议。

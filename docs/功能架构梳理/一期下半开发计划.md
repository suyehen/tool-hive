# ToolHive 一期下半开发计划

> 文档版本：v0.1
> 更新日期：2026-08-24
> 文档目的：将一期下半待实现功能拆解为可执行的功能清单与实施顺序，作为后续任务拆分、开发执行和阶段验收的依据。
> 范围说明：本文不重复列出一期上半已实现功能；正式交付范围与边界以《一期目标》和《一期下半待实现功能》为准。

## 1. 阶段目标

一期下半在现有管理基础上完成最小、可控的 HTTP 工具调用闭环：

```text
管理员维护 Catalog 并审核发布
  → 调用系统携带签名访问运行 API
  → 平台认证并计算当前可见、可执行工具
  → Provider 按固定映射调用外部 HTTP 接口
  → 返回标准化结果，记录 Trace 与审计
```

## 2. 实施前置：先冻结的设计

以下规则属于一期下半实现前置，未冻结前不应将候选方案固化为正式 ORM 模型或对外契约：

| # | 主题 | 需冻结内容 |
|---|------|-----------|
| 1 | Catalog 领域模型 | Provider、能力包、工具、工具版本、执行绑定的实体关系、命名空间、唯一性、环境边界与编码规则 |
| 2 | 状态机 | 草稿、送审、审核、发布、启用、停用、撤回、归档、默认版本切换及在途调用处理规则 |
| 3 | 运行 API 契约 | Resolve、Discover、Execute、确认接口的路径、请求、响应、错误码、版本兼容与幂等规则 |
| 4 | 请求签名 | 签名字段、canonical 内容、请求体摘要、时间窗口、Nonce、密钥选择与轮换规则 |
| 5 | ToolContext | 用户、租户、角色、渠道、会话、追踪字段的传入方式、可信边界、校验与拒绝规则 |
| 6 | 工具调用控制 | 调用系统、业务身份、能力包、策略、工具、租户范围、有效期与拒绝规则的关联方式 |
| 7 | 首批工具契约 | 首批 HTTP 工具的读写边界、目标 API 契约、业务权限、幂等、超时、重试与错误转换 |
| 8 | Provider 出站规则 | 域名/端口/路径白名单、DNS/TLS 校验、请求映射、响应限制、SSRF 防护与健康检查 |
| 9 | 检索与可用性 | Embedding、Chroma 索引、关键词降级、候选数量、覆盖度、索引重建与不可用错误语义 |

阶段 0 的产出为设计结论文档，不直接产出代码。

## 3. 功能拆解

### 3.1 Catalog 管理（配置前提，管理侧）

| 子模块 | 待实现功能 |
|--------|-----------|
| Provider | 创建、修改、启停、归档；目标安全配置（域名/端口/路径白名单、协议、DNS/TLS 校验开关）与环境边界管理 |
| 能力包 | 创建、修改、工具关联、调用系统授权关联、生命周期管理；新增 `capability:*` 操作码 |
| 工具 | 工具编码、命名空间、描述、风险等级、输入输出 Schema、可发现性与可执行性管理 |
| 工具版本 | 草稿版本、版本详情、默认版本、版本归档与发布切换规则 |
| 执行绑定 | 工具版本 ↔ Provider 固定 HTTP 映射：方法、路径模板、参数映射、允许 Header 与响应处理 |
| 审核与发布 | 送审、通过、驳回、发布、停用、撤回、归档、发布历史与状态变更记录 |
| 管理界面 | Provider、能力包、工具、版本、执行绑定、审核与发布页面及操作项控制 |
| 索引任务 | Catalog 变更通过 Outbox 触发 Chroma 派生索引同步，可查询失败与重试 |
| 引用校验回补 | 调用系统工具/能力包范围编码的真实引用校验（一期上仅保存字符串） |

### 3.2 运行入口与调用系统认证

- 建立并挂载 `/api/runtime/v1/**` 路由、服务与统一错误处理链，与管理链隔离。
- 入口标识、可信代理与来源 IP 校验（复用现有入口中间件及一期上 IP 规则）。
- RSA-PSS-SHA256 请求签名验证：识别 `system_id`、`key_id`，校验方法、完整路径、时间戳、Nonce、请求体摘要。
- 时间窗口校验、Nonce 防重放（Redis 共享存储；安全依赖不可用时默认拒绝）。
- 调用系统生命周期、有效期、紧急禁用、公钥状态与密钥轮换的实时校验。
- 认证失败、签名无效、超窗、重放、来源 IP 不匹配的明确错误语义与 Trace 记录。

### 3.3 运行范围与流量控制

- 按调用系统限制可访问的运行 API（`allowed_api_patterns` 实时生效）。
- 按调用系统及 Catalog 状态限制工具、能力包、命名空间范围。
- QPS、并发、日配额、请求超时与熔断控制。
- 紧急禁用、停用、注销、密钥撤销和范围变更立即影响后续请求。

### 3.4 ToolContext 与工具调用控制

- ToolContext 契约：用户、租户、角色、渠道、会话、请求来源与追踪信息；来源、可信等级、格式校验与缺失处理；Trace ID 生成、透传与错误关联。
- 调用控制计算：调用系统 × ToolContext × 能力包 × 工具范围 × 策略 × 租户范围 × 有效期 → 最终允许集合；默认拒绝。
- 可发现与可执行区分；Discover、Resolve 与错误信息不得泄露未授权工具的完整 Schema、目标地址或敏感策略信息。
- 高风险确认：确认申请、确认令牌、有效期、一次性消费与二次校验。

### 3.5 工具发现与执行 API

| API | 职责 |
|-----|------|
| `POST /api/runtime/v1/tools/resolve` | 按工具 ID/编码/版本精确解析；不依赖 Chroma；返回通过范围与策略校验的工具 Schema |
| `POST /api/runtime/v1/tools/discover` | 按自然语言、ToolContext 与调用系统范围检索候选，返回受控候选、排序与覆盖度 |
| `POST /api/runtime/v1/tools/{tool_code}/execute` | 二次授权、版本选择、JSON Schema 校验、参数级安全校验、幂等、Provider 调用、结果标准化与错误转换 |
| `POST /api/runtime/v1/confirmations` | 高风险操作的确认申请、令牌校验、过期处理与防重放 |

Execute 不得依赖 Discover 旧结果，必须重新校验调用系统、ToolContext、工具状态、范围、策略、真实参数与确认状态。

### 3.6 HTTP Provider 与受控出站

- 统一 `ProviderGateway`；所有业务出站（管理、运行）必须经过，不得绕过。
- 仅按已审核固定映射生成请求；调用方与 LLM 不得决定 URL、方法、认证 Header 或未声明参数。
- 目标域名、端口、路径、协议与 DNS 解析结果校验，防护 SSRF（拒绝回环、链路本地、云元数据、多播与未授权私网地址）。
- 强制 HTTPS、证书校验、默认不跟随重定向（如需跟随则每跳重新校验）。
- 限制请求体、响应体、Header 数量、连接时间、读取时间、总执行时间与并发。
- 读/写工具区分超时、幂等、重试与熔断；写操作外部状态不明时不盲目重试。
- Provider 响应格式校验、大小限制、脱敏、标准化与错误转换。

### 3.7 检索、索引与降级

- PostgreSQL 作为工具定义、发布状态、授权与版本的唯一事实来源。
- 嵌入式 Chroma 保存可全量重建的 Catalog 派生索引（复用 `VectorIndex` 接口）。
- 自然语言 Discover 优先 Chroma；不可用时降级为有数量上限的 PostgreSQL 关键词检索。
- 降级候选仍须完成发布状态、调用系统范围与工具调用控制校验，不扩大可见范围。
- 覆盖度判断、候选预算与检索不可用错误语义。
- 通过 Outbox 保证 Catalog → Redis/Chroma 派生数据的投递、重试与失败处理；提供索引重建命令。

### 3.8 Trace 与审计闭环

- `trace_id` 生成/透传，响应与错误关联。
- 记录认证、授权决策、检索、确认、执行与 Provider 结果的关键事实。
- Catalog 管理变更接入现有管理审计并预留 `trace_id` 关联。
- 脱敏：Nonce 原文、签名、私钥、敏感业务字段不进普通日志。
- 一期只做基础 Trace 与基础管理审计，不含审计查询/导出/报表与留存策略界面。

### 3.9 部署交付与验收

- Nginx 运行入口路由、Header 清洗、内网来源限制配置示例。
- 生产配置校验补充（签名、模型 Key、Chroma 目录等）。
- 部署/初始化/验收脚本更新；`deploy/README.md` 更新。
- 首批 HTTP 工具接入（真实外部 API 契约）。
- 端到端验收：调用系统签名 → 认证 → 发现 → 确认 → 执行 → Provider → Trace。
- 阶段文档更新（一期下半待实现功能 → 已实现功能、开发完成情况补充记录）。

## 5. 工程约定

- 数据库结构变更直接修改 `sql/init.sql`，不保留历史迁移（沿用当前阶段约定）。
- 状态约束使用代码层枚举（`core/enums.py`），数据库不加 CHECK。
- 接口时间统一 ISO 8601 UTC；数据库时间字段为 TIMESTAMPTZ。
- 业务表审计字段 `create_by` / `update_by`；关键管理操作接入 `AuditService`。
- 管理操作码集中声明于 `core/operation_codes.py`，启动时同步。
- 后端模块只注入所需配置分区，不依赖完整 `Settings`。
- 测试与实现同步编写；每阶段完成需跑通全量测试与 ruff 检查。

## 6. 实施顺序

| 阶段 | 内容 | 依赖 | 完成标志 |
|------|------|------|----------|
| 0 | 冻结 9 项设计（文档产出） | 无 | 设计结论可指导 ORM 建模与运行 API 契约 |
| 1 | Catalog 数据层 + 管理 API + 管理页面（含审核发布、索引任务、引用校验回补） | 阶段 0 | 管理员可完整维护并审核发布 Catalog；范围编码引用校验生效 |
| 2 | 运行入口 + 签名认证 + 运行范围/流量控制 + 基础 Trace | 一期上调用系统模型 | 调用系统可签名访问运行 API；未授权/失效/重放被拒并留 Trace |
| 3 | ToolContext + 工具调用控制 + 高风险确认令牌 | 阶段 1、2 | 可发现/可执行正确区分；默认拒绝；确认闭环 |
| 4 | Resolve / Discover / Execute / Confirmations（检索先走 PostgreSQL 关键词） | 阶段 2、3 | 运行 API 契约贯通 |
| 5 | HTTP Provider 网关 + SSRF + 超时/重试/幂等/熔断 | 阶段 1（执行绑定）、4 | 固定映射受控出站闭环 |
| 6 | Chroma 索引 + Outbox 同步 + 检索降级 | 阶段 1、4 | 向量检索可用；不可用时可受控降级 |
| 7 | Trace 与审计闭环补齐 | 贯穿阶段 2–6 | 全链路可追溯 |
| 8 | 部署交付 + 首批工具 + 端到端验收 + 文档 | 全部 | 一期下完成判定全过 |

顺序说明：

- 阶段 1 与阶段 2 在依赖上可部分并行（签名认证只依赖一期上调用系统模型），但建议先完成 Catalog：发现/执行/范围校验依赖 Catalog 状态，且文档明确 Catalog 是运行链路配置前提。
- 阶段 4 的 Discover 先以 PostgreSQL 关键词实现，阶段 6 接入 Chroma，确保运行闭环先打通、检索增强不阻塞主线。
- `ProviderGateway` 在阶段 2/4 即立边界（所有业务出站必经），阶段 5 完成执行器与防护细节。
- 每阶段内部按“模型/迁移 → 服务 → API → 前端（管理侧）→ 测试 → 文档”推进。

## 7. 一期下完成判定

以《一期下半待实现功能》第 12 节为准：

1. 管理员可以维护 Catalog，并完成审核和发布。
2. 已登记调用系统可以通过来源 IP、有效公钥签名、时间窗口和 Nonce 校验访问运行 API。
3. 平台可以基于调用系统和 ToolContext 返回允许发现的工具。
4. 平台可以在执行时进行二次授权、参数验证和高风险确认。
5. Provider 只能按审核后的固定映射调用首批外部 HTTP 接口。
6. 检索不可用时可以在不扩大授权范围的前提下受控降级。
7. 请求、认证、授权、检索、执行、Provider 调用和管理变更保留基础 Trace 或审计记录。
8. 管理侧与运行侧作为同一个 ToolHive 应用，具备一期范围内的初始化、网关、配置和基础验收交付物。

## 8. 一期明确不做

实际接入 SSO；MCP Provider / Registry / 平台 MCP 网关；gRPC Provider；工具执行的异步长任务、任务中心、取消、回调与死信治理；高级灰度发布、自动回滚和复杂版本治理；监控看板、报表、在线质量评估和成本评估；多地域容灾、跨地域部署和大规模高可用；目标业务系统凭据代持、Secret Store、`credential_ref` 与依赖目标凭据的 Provider 执行。

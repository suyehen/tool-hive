# ToolHive 一期目标

> 文档版本：v1.5  
> 更新日期：2026-08-16  
> 文档目的：定义一期的最终交付目标、上下半部分范围、前置依赖和明确不做的内容。

## 1. 一期最终交付目标

一期要交付最小、可控的 HTTP 工具调用闭环：

```text
管理员完成配置
  → 工具经审核并发布
  → 调用系统完成身份认证
  → 平台判定当前可发现、可执行的工具
  → Provider 受控调用外部 HTTP 接口
  → 返回标准化结果并留下基础 Trace / 审计记录
```

一期不是两个独立后端项目。管理模块和工具应用模块（运行 API）属于同一个 ToolHive 应用、共享核心数据模型，并作为同一发布、部署、启动和停止单元运行；两者只是在 API、身份凭据和控制体系上隔离。

一期后端生产运行基线固定为 CPython 3.11.6。所有后端代码、依赖版本、构建产物和部署验收必须兼容该版本，不以其他机器上的 Python 版本作为生产兼容性依据。

一期按交付顺序分为两部分：先交付管理模块，再交付工具应用模块。

## 2. 一期上半部分：管理侧目标

一期上半部分提供完整的管理入口、管理安全能力和工具运行配置能力。

| 模块 | 一期目标 |
|------|----------|
| 管理账号 | 支持首个超级管理员初始化、账号创建、临时密码、启用、禁用、锁定、密码重置、强制下线和超级管理员保护。 |
| 登录与会话安全 | 支持本地用户名密码登录、TOTP MFA、恢复码、密码策略、登录失败限制、验证码触发、共享会话、互斥登录、会话撤销与 CSRF 防护。 |
| 后台角色与管理操作项 | 支持账号与角色多对多关联、角色与操作项多对多关联、默认拒绝、超级管理员保护以及页面/API 操作级控制。 |
| 调用系统管理 | 支持按“外部项目 + 运行环境”登记调用系统，生成稳定 `system_id`，维护生命周期、公钥、来源 IP 规则及相关审计信息。 |
| Catalog 管理 | 支持能力包、Provider、工具、工具版本、审核、发布、启用和停用的管理页面与 API。 |
| 管理入口与部署 | 提供管理前端、`/api/admin/**`、`/admin/**` 路由、HTTPS、管理侧基础限流和浏览器安全保护。 |

### 2.1 管理侧权限模型

```text
管理账号 ──多对多──> 后台角色 ──多对多──> 管理操作项
                              │
                              └── 账号最终管理操作范围为各角色操作项的并集
```

- 管理权限只控制管理页面和管理 API，不控制调用系统能否调用工具。
- 管理操作码使用稳定的 `对象:操作` 命名，由代码定义并同步到后端 API 和前端控件。
- 超级管理员自动拥有全部有效管理操作项，但不因此获得运行侧工具调用权限。

### 2.2 调用系统管理目标

调用系统是调用运行 API 的外部软件系统，不是管理账号或最终业务用户。

- 开发、生产等不同环境分别登记，并使用不同的 `system_id`、认证凭据、来源 IP 规则和工具调用范围。
- 调用系统生命周期为草稿、已启用、已停用和已注销；到期状态根据有效期自动判断。
- 启用前需要具备负责人、联系方式、有效认证凭据、来源 IP 规则、运行 API 范围和工具调用范围。
- 停用、注销、密钥撤销等高风险变更必须立即影响运行侧校验。

## 3. 一期下半部分：工具应用模块（运行 API）目标

一期下半部分不提供独立前端，只通过 `/api/runtime/v1/**` 为调用系统提供运行能力。

| 模块 | 一期目标 |
|------|----------|
| 网络与调用方边界 | 运行 API 仅内网开放；Nginx 与应用层共同完成来源网络限制。 |
| 调用系统认证 | 使用 HTTPS、调用系统状态、公钥请求签名、请求体摘要、时间窗口、Nonce 防重放和密钥轮换控制调用系统身份。 |
| 运行 API 范围与流量控制 | 按调用系统限制可访问的运行 API、工具范围、配额、并发、超时和紧急禁用能力。 |
| ToolContext | 明确用户、租户、角色、渠道、会话和追踪信息的传入方式、来源、可信边界和校验规则。 |
| 工具调用控制 | 基于调用系统、业务身份、能力包、工具范围和策略计算请求的工具调用范围。 |
| 工具发现与执行 | 提供 Resolve/Discover、Execute、高风险确认、JSON Schema 校验、标准化结果和错误处理。 |
| HTTP Provider | 提供固定 HTTP 请求映射、受控出站、超时、重试、幂等、响应限制和 SSRF 防护；一期不代持目标系统凭据。 |
| 检索与降级 | 提供工具检索、候选排序、覆盖度判断和检索不可用时的受控降级。 |
| Trace 与审计 | 记录请求、认证、授权、检索、执行和管理操作的基础 Trace、脱敏和留存信息。 |

### 3.1 工具应用模块安全调用链

```text
调用系统
  → Nginx 内网来源限制
  → ToolHive 校验调用系统状态和来源 IP
  → 校验 RSA-PSS 请求签名、时间窗口和 Nonce
  → 校验运行 API 范围与工具调用控制
  → Resolve 或 Execute
  → Provider 受控调用外部 HTTP 服务
  → 返回标准化结果并记录 Trace
```

调用系统认证成功只代表请求来自某个已登记系统，不代表该请求自动拥有任意 API、任意工具或任意业务数据的访问权限。

### 3.2 检索部署与降级边界

- 一期使用嵌入式 Chroma，只部署一个完整 ToolHive 应用实例和一个 Uvicorn Worker；Nginx 不向多个 ToolHive 实例进行负载均衡。
- Chroma 生产持久化目录固定为 `/vdb/tool-hive/chroma`，并使用兼容 CPython 3.11.6 的依赖版本。
- PostgreSQL 是工具定义、版本、发布状态和授权数据的唯一事实来源；Chroma 仅保存可以从 PostgreSQL 全量重建的派生索引。
- Execute 和按工具 ID 或工具编码进行的精确 Resolve 不依赖 Chroma。
- 自然语言 Discover 优先使用 Chroma；Chroma 或 Embedding 临时不可用时，降级为有数量上限的 PostgreSQL 关键词检索。
- 降级候选仍须完成发布状态、调用系统范围和工具调用控制校验，不得扩大工具可见范围；无法形成可靠候选时返回明确的检索暂不可用错误。
- 二期完成共享 Chroma 服务化及索引迁移验证后，才允许部署多个完整 ToolHive 实例。

### 3.3 单进程凭据与出站边界

- 一期保持一个 ToolHive 应用进程和一个 Linux 服务账号，不拆分独立管理进程、运行进程或 Provider 执行器。
- 管理安全、运行安全、检索模型、Provider 执行和基础设施连接使用独立配置对象，业务模块不得依赖完整全局 Settings。
- 调用系统私钥始终由调用系统保管；ToolHive 只保存调用系统公钥。
- 一期不保存目标业务系统密码、API Key、OAuth Secret 或客户端私钥。
- 模型 Key 按开发/生产配置文件加载，并通过配置权限和日志脱敏保护。
- Provider 执行模块只能调用不需要 ToolHive 代持凭据的固定 Provider 映射。
- 如果目标系统需要凭据，该工具转入二期，不进入一期 Catalog 和执行范围。
- 一期不引入 Secret Store、`credential_ref` 或目标系统凭据管理接口。
- 所有业务 HTTP 出站统一通过 `ProviderGateway`，管理模块和其他业务模块不得自行访问任意外部地址。
- 单进程内的配置和模块隔离不等于操作系统级强隔离；一期明确接受任意代码执行后可能跨模块访问进程资源的剩余风险。
- 如果二期引入目标系统凭据且要求管理侧失陷后仍无法访问这些凭据或业务系统网络，再将执行器拆为独立进程或服务。

### 3.4 网关代理与来源 IP 边界

> 一期前提：Nginx 与 ToolHive 部署在同一台 Linux 服务器，ToolHive 只监听本机回环地址，Nginx 是唯一允许访问应用端口的代理。若后续改为跨服务器部署，必须重新确认私网连接、可信代理和防火墙规则。

- 一期管理入口和运行入口由 Nginx 使用不同路由规则区分，但最终转发到同一个 ToolHive 应用端口。
- 管理入口只转发 `/admin/**` 和 `/api/admin/**`；运行入口只转发 `/api/runtime/v1/**`。
- Nginx 清除外部代理 Header，重新写入 `X-ToolHive-Ingress` 和 `X-ToolHive-Client-IP`；ToolHive 只在可信代理校验通过后读取这些 Header。
- ToolHive 应用端口只绑定回环地址，生产防火墙不得开放该端口。
- 管理路由与运行路由必须校验入口标识，入口缺失或不匹配时默认拒绝。
- 运行 API 同时受到 Nginx 全局内网网段限制和 ToolHive 按 `system_id` 的来源 IP 规则限制。
- 调用系统 IP 规则中的 `*` 只允许已经通过运行入口网络限制的来源，不代表公网开放。
- Win11 开发环境可以显式启用仅回环直连；生产必须强制经过 Nginx。
- 后续增加 WAF、Gateway 或公网运行入口时，必须显式配置可信代理 CIDR，不得无条件信任代理 Header。

## 4. 一期必须冻结的前置设计

以下内容仍属于一期范围，但在实现前必须冻结规则，不能使用早期候选方案直接替代确认：

| 主题 | 需要冻结的内容 |
|------|----------------|
| Catalog 与 Provider | Provider、工具、工具版本、执行绑定、能力包、固定执行映射和目标边界的实体关系、命名空间、唯一性和环境边界。 |
| 审核与发布 | 草稿、审核、发布、启用、停用、归档、默认版本切换及在途调用处理规则。 |
| 运行 API 范围 | 调用系统可访问的 API、工具命名空间、能力范围、配额、超时、并发和紧急禁用规则。 |
| ToolContext | 用户、租户、角色、渠道、会话和追踪字段，以及平台对其可信程度的判断。 |
| 工具调用控制 | 调用主体、能力包、能力、策略、工具、租户范围、有效期和拒绝规则的关联方式。 |
| 发现与执行 | Discover 和 Execute 的职责、高风险确认、确认令牌、信息披露和错误语义。 |
| HTTP Provider | 目标地址白名单、DNS/TLS 校验、请求映射、响应处理、健康检查、错误转换和 SSRF 防护。 |
| 首批工具 | 首批只读/写入工具、外部 API 契约、业务数据权限、幂等、超时和重试。 |
| 检索与可用性 | Chroma、Embedding、关键词检索、候选预算、降级、数据部署、容量、备份和验收标准。 |

## 5. 一期明确不做

以下能力不属于一期最小闭环：

- 实际接入 SSO；
- MCP Provider、MCP Registry 或平台 MCP 网关；
- gRPC Provider；
- 异步长任务、任务中心、取消、回调和死信处理；
- 高级灰度发布、自动回滚和复杂版本治理；
- 监控看板、报表、在线质量评估和成本评估；
- 多地域容灾、跨地域部署和大规模高可用架构；
- 大规模任意账号—工具 ACL 专用检索方案。
- 目标业务系统凭据代持、Secret Store 接入和依赖目标系统凭据的 Provider 执行。

## 6. 一期完成判定

一期完成不是仅具备管理页面或配置表，而是以下链路能够以受控方式贯通：

1. 管理员可以维护调用系统和工具配置，并完成审核发布。
2. 已登记调用系统能够使用公钥签名和来源 IP 规则访问运行 API。
3. 平台能够基于调用系统及业务上下文返回允许发现的工具。
4. 平台能够对具体工具执行进行二次授权、参数校验和高风险确认。
5. Provider 只能按已审核的固定映射调用首批外部 HTTP 接口。
6. 调用结果、关键决策和管理变更具有基础 Trace 或审计记录。
7. 管理模块和工具应用模块在同一个 ToolHive 应用中具备可部署的网关、迁移、初始化和基础验收交付物。

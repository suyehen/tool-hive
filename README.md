## 产品定位

ToolHive 是面向 Agent、业务系统及其他服务调用方的统一工具平台。平台将外部系统能力登记为受控工具，并在调用前完成身份认证、工具调用控制、参数校验和受控执行。

调用方或 LLM 只能使用平台在当前上下文中允许发现的工具；它们不能自行决定目标地址、HTTP 方法、认证 Header 或平台托管的凭据。外部业务系统仍负责自身业务数据权限和业务规则的最终校验。

## 单一应用架构

ToolHive 是**一个应用、一个发布单元和一个生命周期单元**。管理模块与工具应用模块都包含在同一个 ToolHive 后端中，统一部署、启动、停止和升级；它们不是两套能够独立部署或独立启停的后端系统。

- **管理模块**：通过 `/admin/**` 和 `/api/admin/**` 提供管理账号、后台角色、调用系统和工具目录等配置能力。
- **工具应用模块**：通过 `/api/runtime/**` 向调用系统提供工具发现、授权判断和工具执行能力。
- **访问隔离**：两类入口使用不同路由、调用身份、认证方式和控制规则。管理账号不能凭后台角色直接调用工具；调用系统凭据也不能访问管理 API。

```text
管理员浏览器                                  调用系统 / Agent
      │                                               │
      └──────────── HTTPS ───────┬── 内网 HTTPS + 请求签名 ──┘
                                  ▼
                 ┌──────────────────────────────────┐
                 │          Nginx / 安全网关          │
                 │ 管理入口保护 · 运行入口网络限制     │
                 └────────────────┬─────────────────┘
                                  ▼
┌──────────────────────────────────────────────────────────────────────┐
│             ToolHive 单一后端应用（统一部署、启动与停止）             │
│  管理模块：账号、角色、调用系统、Catalog 管理                         │
│  工具应用模块：调用方认证、工具发现、调用控制、Provider 执行、Trace   │
│  共享领域能力：Catalog · Policy · Provider · Audit · 配置校验          │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 受控出站调用
                                   ▼
                        ┌─────────────────────┐
                        │ 外部业务系统 / API   │
                        └─────────────────────┘
```

## 核心能力

- **集中工具目录**：以 Provider、工具、工具版本和能力包统一描述外部能力；审核与发布后的定义才可被调用。
- **管理与调用边界**：管理账号负责维护平台配置；调用系统以独立身份访问运行 API，两套控制体系互不替代。
- **按需发现与二次校验**：先根据调用主体和业务上下文返回可见工具，再在执行时对真实参数、资源范围和高风险操作重新校验。
- **受控 Provider 执行**：Provider 仅按审核后的固定请求映射调用外部服务，并负责凭据引用、超时、错误转换、结果清洗和出站安全控制。
- **可追溯治理**：管理变更、认证、授权决策、检索和执行均保留必要的脱敏 Trace 或审计信息。

## 交付阶段

### 一期：受控 HTTP 工具调用闭环

一期交付管理配置到 HTTP 工具执行的最小闭环：

- 管理账号、MFA、会话、后台角色与管理操作项；
- 调用系统、公钥、来源 IP 规则，以及能力包、Provider、工具、版本、审核和发布管理；
- 调用系统请求签名、防重放、工具调用范围、Discover / Execute、JSON Schema 校验和高风险确认；
- 固定 HTTP 请求映射、凭据隔离、SSRF 防护、超时/重试/幂等控制，以及基础 Trace 与审计。

### 二期：协议、治理与规模化扩展

在一期闭环稳定并经实际业务验证后，二期扩展以下能力：

- 企业身份集成，例如 SSO、OIDC、SAML 或企业自有身份协议；
- MCP Provider、MCP Registry / 网关、gRPC Provider 及其他经批准的协议适配；
- 宿主工具与高风险能力治理、异步任务、回调、取消和死信处理；
- 高级发布治理、灰度、回滚、检索质量评估、成本与配额治理；
- 监控告警、审计报表、合规能力、多实例部署、容量治理和容灾能力。

## 典型调用流程

```text
管理员维护调用系统与工具配置
  → 审核并发布工具版本
  → 调用系统使用独立凭据发起签名请求
  → ToolHive 校验来源、身份、防重放和工具调用范围
  → Discover 返回当前允许发现的工具
  → Execute 对真实参数和风险条件再次校验
  → Provider 按固定映射调用外部 API
  → 返回标准化结果，并写入脱敏 Trace / 审计记录
```

## 安全原则

- **默认拒绝**：未认证、未授权、未配置来源规则或关键安全依赖不可用时拒绝请求。
- **固定执行映射**：LLM 不能构造任意 URL、方法、Header、凭据或未声明参数。
- **身份隔离**：管理会话、调用系统认证材料和 Provider 凭据相互隔离，且不出现在普通日志或模型上下文中。
- **双阶段控制**：工具可被发现不代表一定可执行；实际执行必须结合真实参数、业务上下文和风险要求重新判断。
- **受控出站与可追溯性**：对目标服务、网络出口和敏感结果进行约束、清洗和脱敏记录。
